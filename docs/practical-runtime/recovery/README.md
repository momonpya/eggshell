# 中断した実セッションの記憶を再利用する

製品 `7cc1432d…` を変更せず、トークン上限で中断した実CodexセッションのDBを使った。
モデルの回答完了やseed合格とは分けて、保存された観測の再利用を検査する。
[配送前の固定情報](before-delivery.json)と[原文の確認](availability.json)を先に作り、
質問・必要範囲を配送結果から変更していない。追加の回答モデル呼び出しは0。

| 題材 | 全体保存された根拠 | 部分保存を含む根拠 | 別チャット2件のフック時間 |
| --- | ---: | ---: | --- |
| 1 | 3/3 | 4/4 | 4.266 / 3.329秒 |
| 2 | 6/6 | 7/7 | 5.617 / 3.159秒 |
| 3 | 5/5 | 5/5 | 5.612 / 3.256秒 |

[結果](results.json)は全体保存14/14、部分保存を含め16/16。
同じ題材の2チャットは本文がbyte一致し、意味検索・シナプスのpacket検査・正常終了を確認した。
6件は同じDBへの各題材2つの新規チャットでのフック試験であり、回答を蓄積する実モデルの2周ではない。
DBにない末尾の警告やno-outputのコードは未保存として別に示し、配送漏れを0扱いにしていない。

原DBだけからの初回warmは103.975秒。題材2と3は同じ温め済みプロジェクトDBと私有状態を使い、
再warmは1.261 / 1.255秒。題材ごとにDBを複製し、全体を温め直すことはしていない。
初回の構築時間をフック時間や定常時の更新速度へ読み替えない。

配送枠は500,000文字、Codex側の追加context上限設定は0、フック期限30秒。
一般98%、80人の持続利用、p99、総tokenと回答品質の改善をこの試験から主張しない。
実際の本文・stdout・要求・時間・事前の分母・監査結果を各題材のdirectoryへ保持する。
終了した作業DBとcacheは[削除済み](retired.json)。packageの検証用DBも含め、5,326項目・601,353,304論理bytesを削除し、archiveは作っていない。
元の実セッションDBと現行実行体は保持した。記録内の削除済み試験パスを、そのまま再開先として使わない。
