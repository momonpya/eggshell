## Failures, retained diagnostics, and cleanup

The first preparation input omitted numeric/Boolean fields required by the
derived JSON decoder. It was rejected before DB creation, hooks, or model
operations. Its failed guard, raw input, and stderr are retained separately.
Adding the missing fixture fields did not change the product or rerun an actual
query. The subsequent preparation uses a distinct tag and immutable outputs.

The current 30 state files are 994,911–997,559 bytes. Every `lastHandoff` exactly
duplicates its delivered body; that field and `deliveredGraphs` dominate the
file. This confirms an already documented shape from compact-reply and
support-presence; it is **not a newly identified cause** of the old fresh-chat
memory peak. No latency/RSS attribution follows from byte counts alone.
`readState?` may quarantine and write disabled state on parse errors, so its
existing lock cannot be removed as though the function were a pure getter.
No state optimization or new cache is adopted from this observation.

Actual requests, timing/registration receipts, unique stdout, per-query audits,
source freeze, state-width census, failure evidence, and resource/stop records
are retained. Ended trial DB/cache/source/build/control copies are deleted
without an archive: 9,682 entries, 1,532,569,040 logical bytes. Protected source,
runtime/model/native inputs are checked before and after; the surviving
336-object product remains consistent. Deleted data roots are not live handles.

## Scope

These are 30 new native-hook chats against one fixed prepared LLVM DB. They are
not answering-model first/history rounds, a new accepted seed, matched total
token or quality comparisons, a mixed existing/new/resumed multi-DB scenario,
80-user/eight-hour load, multi-host/NAS, or general 98% recall. Adoption and paid
matched comparisons remain zero. The interrupted paid seed is not retried and
its cap is not raised.

Control is `LLVMReadStudy.lean`; source preparation is
`LLVMReadPreparation.lean`, and the existing `TenReaders.lean` workload is
unchanged. Reader retention is factored into `TerminalIntentStudy.retainReadersAt`
instead of copying its verifier. Shared callback audit and dependency-safe
retirement use `AutomaticPublicationStudy.lean`.
