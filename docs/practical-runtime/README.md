## 順序

1. 同じ製品sourceでnative制御器を用意し、製品core/source/linkの監査を通す。
2. 実Pre/Post/Stop、保存workerと索引workerから観測と3辺を作る。関係をfixtureから直接挿入しない。
3. 終了を待ち、元のDBだけをコピーして私有状態のない場所からwarm・復旧・新規チャットの配送を確認する。
4. 実Codexの別チャットを用い、新seed→題材1/2/3→2周目1/2/3を同じ製品で進める。
   保存と索引完了を確認し、配送前にDB-present根拠を凍結する。runtimeを変えたらseedから再開する。
5. 本体・README実績・releaseへの採用は、AGENTS.mdの同条件・同数複数反復・総token・品質・期限の検査後に判断する。

インストール済み公開版とこの隔離した開発製品は別物であり、開発側の検査成功だけで
利用者の既存インストールを更新済みとは扱わない。製品へ採用されていない候補で実利用のDBを上書きしない。

終了済み候補と旧制御器は削除し、[削除後の新しい制御器](native-after-retirement.json)も330 objectが整合している。
