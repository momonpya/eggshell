# Keep the original domain separate from retrieval truncation

This is an isolated development candidate. No production/README/release adoption
or total-token improvement is established. The fixed product seed remains C7;
the following changed runtimes are tested only by model-free replay on its
unchanged frozen checkpoint.

## Why an earlier success did not prevent this failure

The October 23 source-record candidate delivered every then-frozen first-topic
item in two chats (20,223 / 16,717 ms). Its full six-stage missing counts were
0/0/1/1/0/0, so it was not a general all-stage delivery success. Its first-topic
requirements also differ: the current seed includes tracked input-language
state, whereas that older first-topic list included default-toolchain selection.
The common trailing warning really was delivered then and is missing now.

The old record-closure source and the C7 runtime's source have the identical
SHA-256 `5fab3142399728001dd71462ab8a5e73e10f66f508b48d6371237d9e24090bbc`.
The old fix was not removed. However, the original hook integration in commit
`7c8dde3` already disabled the prepared original-row route whenever the separate
500 ms synaptic walk was incomplete. The current seed hits that condition in
both first-topic chats. A bounded recommendation walk could therefore disable
the independent, already checked source domain.

Removing that coupling alone still delivers 2/4. It is one demonstrated defect,
not proof of a single cause for the complete difference between seeds. The
older DB has been deleted as requested, so the retained old reports and source
hashes cannot be presented as a new same-snapshot regression replay. Regression
coverage must include incomplete graph expansion and different original-output
layouts; an earlier successful seed is insufficient.

## Complete original-record candidates

`CanonicalSource.Records.catalogue` enumerates complete bounded records plus
original rows that belong to none. It takes no query, focus list or human
reference. A hash set avoids rescanning all records for every fallback row.
Ordinary Lean proofs establish that every original index appears in the domain
and that candidate payloads come from the original array. Read gaps supply no
invented lines. Real file/origin/Work identities remain separate from payload
sharing; no Match, Union or completed authority is created.

The actual first-topic owner has 431 units and 61 selected units. Both missing
intervals now have **no candidate-domain gaps**, but neither is selected. Replay
still delivers 2/4 in 15,442 / 12,539 ms, with byte-identical stdout
`e3903d98a67d067272f89eddaa32068716883724f00ec6fb0237d9d81ad13546`.
This intermediate candidate is not accepted. Its original-row checks and a
freshly compiled oracle/ContractAudit pass; these do not substitute for delivery.

A native read-only inspection binds the recorded family to its actual source
Work and output lengths. In both chats, **none of its retained focus windows
touches either missing interval**. All source facts are unchanged. The next
change therefore addresses the evidence boundary, not selector weights.

## Separate rank evidence from foreground repair

The provider had scored every focus window, then retained only 16. The client
also used the 32-window repair type to validate already scored evidence. The
downstream fitter consequently assigned no direct focus value to discarded
original ranges. Complete record availability alone could not repair that loss.

The complete-focus candidate changes this boundary:

- `WindowPull` still permits at most 32 original windows before invoking a
  foreground reader.
- `WindowEvidence` is bounded by the actual immutable source directory,
  verifies distinctness and resolves only original finite indices.
- `WindowOrder` verifies a complete permutation. Focus rejects a reply that
  loses an already scored original window. Its Lean coverage theorem holds for
  every window in that directory.
- Focus appends scored positions and sorts once at the end. It does not sort
  an ever-growing list after every score. Discovery retains its existing
  bounded nomination evidence; this does not initiate a full DB scan.
- The encoder, cached vectors, owner score, owner nomination policy, existing
  RRF coefficients, original authority/freshness and wire budgets are unchanged.
  Downstream selection may change intentionally because lower focus ranks are
  now available.

The product SHA is
`56475bf9e268504fc136c8bb076c1bb970ad78dbdbc2c4617e0bde500b7948bf`.
Native regression checks cover counts 0/1/16/17/32/33/127/512, incomplete and
duplicate/foreign replies, the unchanged repair limit, unchanged owner scores
and previous top 16, preservation through later fusion, and the lexical-only
provider round trip. FullSearchOracle was freshly compiled against the candidate
before ContractAudit. Interpreter failures on native numeric/filesystem symbols
are retained; the successful probes use the product's actual native link inputs.

`BuildNativeProbe.lean` compiles a separate research entry point against that
captured object closure, removing exactly its original Main object. It does not
rewrite the product binary or its interfaces. Human reference ranges are used
only by the later read-only delivery audit and never enter the product request,
ranker, source catalogue or fitter.

The first real replay exceeded the worker's delivery boundary at 28,955 ms and
returned an incomplete notice. Its guard closed without survivors. A subsequent
CPU diagnostic used distinct new chat IDs on the same frozen source; both
replies had the same body, took 27,705 / 27,598 ms, and delivered 3/4 items.
Language tracking and the warning were now present, while the complete HLSL
branch was absent. This is a failed delivery candidate, not a latency acceptance
result. The earlier accidental reuse of deterministic preparation session IDs
returned `{}` and is retained as an invalid diagnostic, not a successful empty
answer.

## Prepare original records once, independently of query windows

A one-second native CPU sample found 480 of 555 active preparation samples in
the old per-window preparation route: repeated original decoding, prefix
verification and contextual view construction. It did not identify the greedy
selection step as the sampled bottleneck. The next candidate therefore changes
the preparation unit, without tuning rank weights or adding command filters.

Each admitted original output obtains one layout and a complete catalogue of
bounded original records. Record gaps, including JSON framing, remain original
candidates. Focus and dependency hints supply values; their presence does not
decide whether the original characters exist in the candidate domain. Native
text, JSON, Unicode and MCP output use this same route. Already prepared file
records keep their own catalogue and file provenance. A raw output does not
gain a file alias, Match, Union or completed authority through this change.

`original_record_fragment_exact` proves that every fragment is precisely its
original character interval. Indexed slicing works on the selected interval,
without repeatedly traversing the preceding output. Optional scalar display
decoding checks the whole canonical JSON scalar once and restricts endpoints
to encoded character boundaries; it does not infer coordinates for a
noncanonical escaped scalar. Raw evidence remains separate from presentation.

Native checks cover six cases: empty output, multilingual text with escapes,
canonical and noncanonical JSON strings, a JSON object with a field exceeding
6,000 characters, and 5,000 Japanese characters. They check candidate-domain
coverage, original coordinates and payloads, 2,048-character bounds, display
round trips and absence of control authority. A freshly compiled oracle and
ContractAudit also pass. The audit now follows `prepareOriginalRecords` to the
checked range projection and indexed original slicing, rather than requiring
the removed per-window call structure. The initial audit failure is retained.

The product SHA is
`230f4cc723a07c24133ce6eaccad8e8a2b9a961aa0039cc5c4926f8e598dd04d`.
Two independent chats took 26,504 / 24,933 ms with byte-identical stdout
`d2fa736bb3ce9e2ccfd57325c5b003d99386ae6bd8965bfa38f66f8ed9b92900`.
Both delivered 2/4: language tracking and the warning were present, while the
cache key and complete HLSL branch were absent. This candidate is not adopted.
Source facts and the published page prefix remain unchanged. Aggregate RSS
peaked at 2,502,240 KiB and the guard closed without survivors.

Recorded selection traces place both missing HLSL alternatives in the original
domain. One owner has 708 candidate units, including an exact 523-character
complete branch, but no selected unit. That complete unit's standalone charge
is 2,246 characters / 2,250 bytes, including its shared operation/provenance
envelope. Availability and complete focus evidence therefore do not alone
solve this selector failure.

## Account for shared activation during look-ahead

The next isolated candidate adds an original-offer recipe for a shared source
envelope. It sorts that owner's offers by payload density, evaluates every
prefix using the actual unions of cost nodes and cues, and retains the best
feasible density prefix. Its final charge includes the complete envelope once;
it is never discounted. All original singleton offers remain eligible. There
is no added relevance, reserved quota, fitted threshold, command rule or human
reference in this proposal. This is a deterministic look-ahead heuristic, not
a global optimality or approximation-ratio claim.

`Activation.original_parts` proves the recipe contains only supplied original
offers; `Activation.no_bonus` proves it adds no cue. Existing closure-expansion
proofs still connect compiled proposals to the exact original cost union.
A native shared-setup example exposes the failure: ordinary selection gains
60, while combining three original records gains 120 at an exact cost of
104 within a 110 limit. Duplicate records do not create votes or costs, and an
unrelated setup produces no proposal. Actual question delivery is a separate
gate; passing this example does not establish that it improves it.

That product (`e71877c8eca288250d9c33d393ed256201f35e2ea9ab4a6a9a32ba06e6d64c67`)
still delivered 2/4 in both actual chats, at 26,766 / 25,400 ms. Stdout was
byte-identical (`bd41d17ab7ed4962aa4b17897ae2ecb11d81b911cbf4d00302b923aaf8d95f44`).
Aggregate RSS peaked at 2,334,864 KiB. It is not adopted. Further selector-weight
or setup-frontier trials are stopped; this failed result does not justify
promoting another surrogate objective.

## Check the missing relation, not just the final chooser

The recorded source walk again ended at 233 requests, with `complete=false` and
no admitted offer. A native model-free diagnostic reconstructs answer roots
and consumer roots from the recorded nominations, hydration and immutable
original occurrences (8 answer / 7 consumer roots). Giving the walk diagnostic
time does not remove its separate 256-request work cap: it stops there after
763 ms, with 646 checked offers discarded. With a diagnostic bound derived
from the pinned index population it completes 2,086 requests and 4,341 checked
facts in 1,951 ms. This is not a larger product-hook budget or a complete
Transport/selection replay. The product budget and limits are unchanged.

The complete diagnostic's admitted range offers do not cover any of the four
frozen required originals; comparing output producers with their saved native
occurrences also finds no corresponding proposal. Simply increasing the
deadline therefore cannot be claimed to supply the missing evidence.

`SynapseSource.recordedRows` still calls `readPlans (workCommand work) files`.
That plan recognizes literal `nl -ba PATH | sed -n PROGRAM` sequences. The
independent original-output route handles other data, but source-coordinate
and graph normalization remain conditional on that old command grammar.
Calling the earlier work generally command-independent was insufficient.

The next implementation boundary is ingestion correspondence:

- Match original output records against the **actually acquired, fingerprinted
  input contents**, independently of the tool/command name. Do not read human
  reference files or assume an output is source code.
- Preserve exact original offsets, optional structured field paths, input
  identity and every real observation origin. Persist checked correspondence
  with the original publication so a new chat needs the DB alone. Shared
  payload identity must not merge Work, execution identity or permissions.
- Build an inverted content index once per acquired input; resolve duplicate
  lines through consistent neighboring anchors. An ambiguous match remains an
  original-output address, not an invented file coordinate. MCP/opaque data
  with no file counterpart keep original record/field identities.
- Use bounded streaming and the same publication delta for canonical rows,
  the three relation views and vector/lexical views. Do not copy a whole tree
  or require Git. Check input changes while capture is pending and retain the
  original body when correspondence cannot be established.
- Only after this is wired through real Pre/Post/Stop, test new empty-DB seed
  capture, freeze original availability and rerun topics 1/2/3 and lap two.
  Keep the existing failed 2/4 results and denominator; do not relabel them as
  successes or accept code from component proofs alone.

This remains query-time preparation once per admitted owner, not proof that all
records have already moved to publication-time views. Actual body delivery and
deadlines are evaluated separately. A changed product still requires a fresh
fixed-runtime seed before the answering-model study. Six real answering stages,
repeated matched inclusive tokens, quality, million-window and team/NAS
acceptance remain unfinished.
