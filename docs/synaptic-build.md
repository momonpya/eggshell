# DBを直接読むLean抽出器

`Eggshell/SynapseBuild.lean`は固定したPageMap出版とNodeReaderから、元観測の範囲・引用支持・共引用を構築する。
エクスポート用JSONやPythonの抽出処理を介さない。手動の版番号を追加せず、保存索引の実装印にこのLeanソースの実バイトも含める。
Lakeでもその入力ファイルを明示的に追跡し、通常の増分ビルドが古い実装印を残さないようにする。
観測には元DB・所有者・Work・原文座標を保持し、所有者の表示ハッシュに複数のlive候補があれば拒否する。

## 初回と増分

初回の明示warmではlive候補のヘッダと本文を読み、対応できる番号付き観測と回答の引用を処理する。
未対応の読み取りや曖昧な観測から、存在しない原文範囲を補わない。未対応数は結果に残す。

通常の準備状態確認は索引のhead・manifestと最大16件の中立な変更ジャーナルだけを読む。本文も索引事実全体も読まず、書込みもしない。
準備済みの再実行は索引headを変えず、本文の具体化は0件である。

背景更新では前回と今回の完全な親headの鎖を確認し、追加・撤回されたOutcome、出典証明書、All関係から影響したWorkの祖先を求める。
関係のメタデータは背景側で走査するが、無関係な原文本文を再具体化しない。
新しい回答は、自身と引用対象になった保存観測だけを具体化する。以前は支持できなかった回答も、新しい観測がその子に入れば更新する。
変更された観測に依存する古い支持・共引用を取り下げ、新しい事実・全逆引き・入力headを一度に出版する。
非祖先の入力や実装印の変更は全再構築の対象で、古い入力が新しい索引を上書きすることは保存層が拒否する。

`retained_support_independent`は、残す支持が変更対象の観測にも回答にも属さないことを、実際の保持関数について証明する。
`usage_never_enters_shared_rebuild`は同じ関数が私有利用記録を共有索引に取り込まないことを証明する。
取得した関係の有効性・要求キーへの所属は既存の`Lookup.returned_bound`で検査する。
これらは推薦の保存・取得の性質であり、Match・Union・completedや現在のファイル一致の証明ではない。

## 実時系列の扱い

保存DBの包含関係や番号からツールの開始・終了時刻を捏造しない。
`consumed`は実通知の時系列を使う既存Lean抽出器の責任で、DB由来のこの構築器は新しい消費辺を生成しない。
入力が前回の子孫で、撤回がない増分では既存の消費辺を保持する。撤回時は保守的に取り下げる。
実通知からの再構築や、実Pre/Postからの私有利用eventの追記は今後の接続である。
実装印が変わって全再構築になる場合も、元の時系列から消費辺を再生する必要がある。

## warmへの隔離接続

`candidates/synaptic-warm.patch`を隔離checkoutへ適用すると、`Warm.runTarget`と背景`Worker.indexQueued`が同じLean構築器を呼ぶ。
派生索引のclaimは数値索引のclaimを取る前に完了させ、入れ子のロックを作らない。
ネイティブ抽出が失敗したら数値索引チケットの削除まで進まない。
フック側は上限付きの準備状態確認だけを行い、本文の抽出や全事実の読み出しを開始しない。
数値チケットがなくても未準備のシナプス索引を背景workerへ送る。
本体のWarm/Worker/PluginHooksへの適用や、インストール済み実行体の差し替えはしていない。

ネイティブ統合試験では、窓0件の`Warm.runTarget`が存在しない数値プロバイダを起動せず索引を準備し、再実行で索引headが一致した。
背景`Worker.indexQueued`は数値チケット0件でも実seed DBから144関係を私有領域へ構築した。
PluginHooksの候補もwarningAsErrorでコンパイルしたが、実フックからの配送、非空数値バッチ、3種類の辺を使う選択はこの試験の対象外である。

## 検証結果

`tests/SynapseBuildTests.lean`をネイティブ実行し、初回・再利用・無関係な追加・新規引用・後から加わる元観測・
出典証明書の撤回・Allの撤回を確認した。17件の派生メモ更新も、本文0件の背景更新で追い付いた。
観測追加後と関係撤回後の2出版では、同一headの原ファイルだけを別ディレクトリへコピーした冷状態の全構築と、増分結果の全事実が一致した。
DBの包含から実時系列や利用記録を作らないことも検査した。

凍結seed DBでは37候補から読み取り44区間、引用支持34件、共引用66 incidenceの計144関係を234msで構築した。
以前のLean抽出結果のDB由来部分と、事実・元所有者・原文座標まで完全一致した。
未対応観測は21件と明示し、以前実RPCから抽出した464消費証拠をDBだけから再現したとは扱わない。
別プロセスでの再実行は本文0件・索引追記0・1ms。これらはmain内の計測で、実フックやモデルの遅延ではない。
元DBのhead・ページファイルは前後のSHAが一致した。
測定に回答モデルは使っておらず、総トークン改善や最終採用は未検証である。

成功・失敗の資源記録、実行体と入力のSHAは`candidates/synaptic-build-review.json`に保存する。
次は実Pre/Postと受領記録からの消費・利用の継続更新、その後に推薦・配送への隔離接続を行う。
