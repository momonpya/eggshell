# 初回配送に向けた研究仮説

2026-10-28。提案であり、実装・新規性・配送改善・総token改善は未検証。本体へ採用しない。

## 狙うもの

新しいチャットの**最初の質問**で、既存の許可されたsnapshotから必要原文を配送する。同じ質問を一度解いた後の回答、再読、利用ラベル、凍結正解を必要としない。既存の利用信号は補助であり、初回の失敗を後の成功で置き換えない。

有望な仮説は、シナプスを単なる候補の点数や到達可能性へ潰さず、**参照とその解決に必要な原文の条件を保存し、質問ごとに未解決の依存を閉じる**ことである。

今回の診断では、配送済みの原文に関数呼出しがあっても定義が落ちている。単語の希少性と未見文脈を加えた診断でも、必要な全体recordは183候補中25位だった。必要なのは、同じ語を持つという信号より強い「この位置のこの参照を、このscopeと入力版のどの観測が解決するか」という関係かもしれない。この一例から全ての欠落原因を一般化はしない。

## 方法の候補

1. 出版差分で、原文範囲、入力snapshot、scope、時系列、参照元と解決候補の対応を準備する。コードの定義/使用、構造化データの資源参照、ツール間の入力/出力消費を、原文の証人を持つ共通の参照関係へ載せる。未知の形式を捨てず、原文の通常推薦を残す。参照の抽出には形式ごとの解釈が必要で、任意のテキストの意味をハッシュだけで復元できるとは扱わない。
2. 条件をAND、代替をORとして区別する。例えば、ある原文を引き継ぐ際に必要な参照先はまとめて扱い、同じ参照を別の取得経路が解決するなら代替として保持する。同じ回答に共起した全観測を必要条件にはしない。3辺のヒューリスティックな提案と、確認できた参照の対応を区別する。
3. 質問とMiniLMは入口の提案に使う。入口の各候補について、未解決の参照と、その解決に必要な原文の増分費用を求める。先に120,000文字を埋めてから不足を足すのでなく、依存を含めた候補を比較する。全隣接先の無条件な推移閉包は作らない。
4. 物理的に同一の原文は一度だけ払い、代替経路の共有を保つ。正確な内容・範囲・scopeの同一性だけを共有の根拠にし、類似度を等価性にしない。循環参照は有限の成分として扱い、全証拠集合の列挙や全起点の閉包の保存はしない。厳密な最小費用抽出が簡単とは仮定しない。
5. 抽出後に、選んだ依存と実際の配送bytesの対応を検査する。Leanで保証する対象は、scope、原文の同一性、選択した条件の閉包、費用、推薦から認定へ流れないこと。条件の抽出自体が質問の意味に対して完全・正確であることや、95%の必要履歴を届けることは別の実測課題である。

これは、過去回答の予約、無条件な束の優先、全体の代理被覆の最大化、同語の得点追加とは異なる仮説である。ただし、依存の判定が単なる同語照合へ戻れば今回の否定結果と同じになる。退役した`source-definition-cues`の単なる再実行にしない。旧試行の実装本体は今回確認したGit履歴にはなく、文書には退役と非汎用規則の禁止だけが残っていた。旧試行との差を確認できるまで、関数定義の検出器を作ることを進捗にしない。

## 既存研究との関係

- [HippoRAG](https://arxiv.org/abs/2405.14831)は知識グラフとPersonalized PageRankによる連想検索を行う。辺の追加や活性伝播だけを新規性にしない。
- [DyRetriever](https://arxiv.org/abs/2608.01927)はLLMで入口・依存関係・探索先を選び、部分依存グラフからコードを取得する。依存グラフによるコード検索自体は既存である。
- [Certify](https://arxiv.org/abs/2610.34684)は質問ごとの要求hypergraphとHorn閉包で根拠の充足を判定する。要求とリンクが正しいことが保証の前提で、質問分解や根拠のlinkingにはモデルを用いる。AND/ORや条件付きの証明書だけを新規性にしない。

研究として狙う差は、**保存済みのnative軌跡から差分で準備する依存表現、照会中の追加生成LLMなしでの初回配送、複数DBのscopeを保つ原文共有、厳密な認定との型上の分離**を一体で成立させ、その費用と効果を示すこと。ただの組合せを新発明と呼ばず、最も近い方式との比較で差を確かめる。

## 最小の検証

最初は製品を変更しない。保存済み原文だけで、実配送側に現れる参照が何を未解決にしているか、対応する原文の証人があるかを監査する。今回の正解位置や関数名は抽出器の入力にしない。関係が得られなければ、その依存があると仮定した選択実験へ進まない。

その後、同じsnapshot・予算で現4/5候補と隔離候補を比較する。単なる同語辺、pairwise展開、条件付き依存を外した対照も区別する。保留した初回質問でも、配送前に原文存在と必要範囲を凍結する。質問の回答後に得た情報は初回の成績へ混ぜない。

配送、依存抽出精度、期限、RSS、出版差分の費用を別々に測る。95%と数秒は目標であって、この提案から導く定理ではない。製品の採用には、最新AGENTSの同一条件・事前同数複数反復・初回/履歴あり×題材1/2/3・cachedと失敗を含む総入力+出力token・品質・deadlineの比較を要する。
