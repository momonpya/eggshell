# Leanによる実ログの導出来歴と任意索引の失敗処理

隔離候補であり、総トークン改善・回答品質・最終採用は未確認である。
抽出・照合・辺生成・利用判定・原文配送の実装はLeanに置く。
旧Python抽出器を再利用せず、既存のMiniLM数値境界と資源監視は変更していない。

## 実ログから元観測へ結び付ける

`SynapseImport.lean`は、凍結したRPCの実測`monotonic_ns`、開始/完了通知、
完全なsession/turn/item ID、呼び出し、出力全文を読む。
固定native出版に属する元観測について、ID・呼び出し・復号した出力全文が一致した場合だけ移行する。
部分文字列・近い行番号・類似度・DBの列挙順を代用しない。未記録の時計や出力は不明のまま残す。

録画ファイルの実バイトから時計領域を導き、独立した録画やlive daemonの時計を混ぜない。
逆行・非正の区間・同一観測の呼び出し/出力競合を拒否する。重複通知は最初の観測時刻を保持する。
既存の導出来歴がある観測は、その時計を別の録画の時計で上書きしない。
これは観測された順序と文字列による推薦用の推測であり、ツールの必要性・操作同値・因果性を証明しない。

`Bound.native/exact_occurrence/exact_invocation/exact_output/observed_order`で、
照合済みの値が持つ5条件をLeanで証明した。`sorry`・`native_decide`・新しい公理は追加していない。
非認定メタデータの出版と権限保存は既存の`SynapseProvenance`を使う。

`tools/SynapseImport.lean`の`plan`は書き込みを行わず、`apply`だけが明示したDBへ来歴を出版し索引を更新する。
既存seed31コマンドでは26件が厳密一致、5件は出力不一致だった。曖昧な一致と呼び出し不一致は0。
移行したコピーから、原文行に結び付いた消費の事実227件を復元した。旧方式の抽出件数と同一視しない。
手動の正解範囲・現在の質問・後続の利用ラベルは移行器へ渡していない。

`SynapseImportTests.lean`で非native・別観測・呼び出し違い・部分出力・欠けた時計・
逆行・同時刻・重複・競合・所有者の曖昧性・再送・権限不変・DB単体での再構築を検査した。
`SynapseImportSix.lean`は元の6snapshotを変更せずコピーだけを移行する。
全段階で元のグラフ/認定行と既存ページのバイト列が不変、元snapshotのSHAも不変であることを検査する。

## 壊れた任意索引を通常配送へ持ち込まない

`SynapseRecommend.prepare/Prepared.collect`で、任意の共有/私有索引を開く例外と読み取り例外を受領する。
失敗した探索は未完了として候補を破棄する。`Result.failed_not_admitted`でその条件を証明した。
途中までI/Oした可能性があるため、失敗時の要求数・事実数・バイト数は0ではなくnullとし、理由と既知の索引headを記録する。
候補が空なら`SynapseTransport.build`は余分な原文射影を行わない。

単体試験ではpostingを残して元事実だけを削除し、例外が通常配送まで伝播しないことを確認した。
実Pre/Post/Stop・新規チャットのUserPromptSubmitでは支持/消費/共引用/未配送後再読から原文が届く。
その後に同じ任意索引を破損させ、通常の配送本文とバイト一致、completedと現在の操作省略の結果が不変であることを確認した。
completedは基準・候補とも1、現在の操作省略は両方falseである。
この検査は任意の推薦索引のI/O例外を対象とし、元DBの破損を隠すものではない。

## 検証と適用範囲

Leanの`warningAsError`コンパイル、上記の証明依存、凍結候補と対応する既存ContractAuditを検査した。
通常worktree全体のビルドやinstalled実行体への適用とは区別する。
実装・runtime・再利用リンク入力・実行体・計測器・入力は6段階実行前に`frozen-inputs.json`へ固定した。
成功と失敗の資源guardを保持し、回答モデル/seed呼び出しは追加しない。
同じ6問での重み探索を再開せず、初回題材1から全6段階の配送を再監査する。
配送検査だけを総トークン改善に読み替えない。

段階内の2本文はバイト一致、保存原文の座標を確認できなかった項目は0だった。

回答モデル/seed追加0、総トークン削減率・回答品質・最終採用は未確認。
