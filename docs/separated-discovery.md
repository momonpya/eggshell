# Separate recognition from recommendation

This isolated Lean candidate replaces indexed discovery's all-Work partial-text
inference with two explicit producers. The e-class query supplies original
owners and generated equality; numerical or lexical nominations supply original
data as advice. The existing source graph, three synaptic edge types, focus,
packing, freshness, extraction and native ACK protocol remain connected.
No product implementation, README result or release is replaced.

## The change

`WorkEvidence.nominated` carries neither Coverage nor equality. It stays advisory
and generates no Union even if the old `retrieved` flag is changed. Ordinary Lean
proofs cover that stronger property and preservation of the original result.
`identified` retains its real generators, original owner and child witness.
Its complete original class query has no recommendation K limit.

The controller no longer calls Work-surface postings, individual Work views,
Work-frequency inference or geometric alignment. Its source adapters retain
the complete original class/child lookup. Unpublished observations also consult
the global source child index; a regression caught and corrected that missing
lookup. Existing extraction still checks the current generated quotient.
ContractAudit checks the actual two constructors and rejects the removed
inference dependencies from this controller. Work-alignment rank/selection
memo readers are no longer opened by automatic handoff.

This intentionally removes heuristic partial-string Union generation from this
controller. It is not an extensionally equal implementation of that old rule.
Thirty-two fixed comparisons retain every difference: fourteen initial replies
change; eighteen cases agree completely. Raw completion/blocking totals fall
from seven/five to three/three. Exact literal and staged child recognition stay;
quote rewriting and subcommand reuse need the planned tool-semantics rules.
The unverified external fixture can be classified before freshness, but the
actual source-check API clears its completion and control.

Nominated Match rows retain original publication order. A preliminary native
comparison exposed unnecessary changes to two graph listings; the stable-order
correction makes both 10k bodies byte-identical to the stored reference. It
does not alter numerical ranking. No source name, question or answer key enters
the runtime rules.

## Verification and current limits

Final ContractAudit, its refreshed proof dependencies, MatcherFixtures and the
new nomination contract pass with ordinary Lean axioms only. The API covers
literal/congruence identity, original data, cross-DB membership, stale/missing
source evidence and unverified MCP output. Four small actual native PreToolUse
cases retain stdout/publication SHA and accepted memory ACK agreement: unchanged
sources control the covered operation, changed sources do not. Those native
cases precede the final publication-order-only correction; they are not scale
qualification for the final binary.

A guarded harness makes individual Work reads, surface postings and Work
frequencies throw. It still delivers from the original 10k publication in about
0.1 seconds with eight nominated owners. Metadata setup and the numerical
provider are outside that controlled timing. This is evidence that the former
per-owner inference is gone, not an end-to-end latency claim.

Actual final-binary UserPromptSubmit results use the original read-only sources,
real MiniLM, a new private question/chat state, explicit warm, daemon and native
stdout/ACK protocol. These are one pair per source, not p99 or token cohorts.

Both 10k bodies exactly match the corresponding stored projection-fold bodies.
That is a stored-body check, not a new matched speedup comparison. The 50k first
reply improves on the old notification-only failure but the continued reply is
still a failure. `replyComplete=true` certifies stdout publication, not completed
search; the trace and `offerAccepted=false` expose that distinction.

The 50k trace spends about 14.3 seconds until semantic timeout, followed by about
13.4 seconds in the lexical lane. The lexical receipt records 399,753 posting
rows and 1,199,259 point keys over nine terms; validation repeats for overlapping
owners. It spends about 4.4 seconds preparing these reads and 6.7 seconds inside
postings. The hook still opens the now-unused prepared Work index and separately
looks up lexical candidate ordinals. Those are the next concrete reader costs.
The semantic policy currently gives at most 15 seconds and half the available
time, which also prevents the larger numerical query from completing.

Prepared domain metadata and full numerical scoring remain proportional to N.
Normal federation still builds its global catalogue. Many same-Work owners or
large Union sets remain unqualified. The old flag-only similarity control must
also be redesigned: nominated evidence now resists promotion by that flag.

## Resources and next step

The aggregate guard remains 3.5 GiB below the 4 GiB user ceiling. The final direct
build peaks at 2,129,360 KiB; the 50k run peaks at 2,244,544 KiB. An erroneous
overlap of an earlier build and proof was recovered by the guards at 3,018,208
KiB; it is retained as an invalid execution, not described as serial success.
An earlier 50k preparation was disk-stopped before any hook. The later warm
finishes and publishes the numerical projection; preparation time is excluded
from the table. Source embeddings and explicit warm statistics are recorded
separately in the review.

Closed older compiler caches, unused executables and a failed-link temporary
were hashed and deleted without archives. Current/reference runtimes, the active
compiler cache, original DBs and raw receipts remain. Source root file hashes
are unchanged. An early attribution of disk loss to private cache growth was
unsupported; the recorded small partial cache alone did not explain it.

Next: remove unused Work-index opening, reuse original owner validations within
one pinned lexical request, retain their ordinal witnesses for ranking, and
reserve a measured fallback interval instead of automatically halving the
semantic window. Keep original source checks; do not solve this by trusting
derived postings as completion authority or hiding failed continuations.

The [review](candidates/separated-discovery-review.json) pins the patch, sources,
caller objects, raw records, failures and scopes. No answering-model calls, new
seeds, inclusive-token or quality comparisons occurred. AGENTS.md adoption gates
for topics 1/2/3, both laps and equal predeclared repetitions still apply.
Phases 0–6 remain active and unfinished.
