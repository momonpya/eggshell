# Publish the public capture record during preparation

Isolated experiment after `a00aa07e`, **not adopted or retained as the next
implementation base**. Runtime `96baec7f…`; contemporaneous parent `b996ee9d…`.

Preparation already knows the complete input roots and one source's owner
descriptor. The ordinary frontend nevertheless reopens the input B-tree and
owner book independently for each source and captures private usage again.
This candidate publishes a bounded combined public read projection alongside
the existing 64-publication input directory. Ordinary capture reads that record
directly, validates its source, producer, model and project scope, then attaches
the original independently captured private usage boundary. It does not build
candidate domains, original-line mappings, vectors or synapse edges in a hook.

There is no new shared lock/CAS or per-user/question cache. Independent source
owners and publication/preparation worker limits remain unchanged. Atomic file
replacement is the existing filesystem boundary; it is not claimed to be a
proved multi-host filesystem primitive. A record can advance when derived
readiness changes without changing the original source head. Captured frames
hold immutable values, rather than rereading that live name later.

The small projection is additional derived metadata, not another vector copy.
The existing bounded input book still controls retirement; it is also an
independent reference for the native comparison. Empty/metadata-only original
publications and different storage locations must preserve the existing read
inventory and owner behavior. A missing record must not silently remove a
source, replace a retained head with latest, or trigger construction in a hook.

This step removes B-tree lookup work before admission. It does not yet establish
service-wide reuse of decoded public metadata, eliminate the search queue,
establish eighty-person sustained capacity, prove IO concurrency, or meet the
98% original-evidence goal. Adoption additionally requires the matched total
token/quality/deadline gate. Answering calls and paid comparisons remain zero.

## Results and decision

The native audit compares all sixteen public input/owner records against an
independent input B-tree lookup and the existing owner-book lookup. The complete
frames agree. It rejects omitted/reordered/foreign/private descriptors, observes
same-original readiness changes without mutating captured values, and exercises
a filesystem-read-only original with private publication metadata and independent
database-resident owner roots. Missing preparation in a mixed-project inventory
does not produce a ready subset. Once prepared, all eighteen mixed sources are
captured. The ordinary ContractAudit passes. These are not full concurrent IO
or directory-retirement proofs.
