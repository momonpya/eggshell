# Public and private preparation ownership

Isolated candidate, not adopted. A logical project retains its independent
append owners. A physical original head has one current publisher; different
original heads can publish concurrently. The service schedules source writes
outside its short queue-metadata gate. Eighty clients do not require eighty
physical owners, nor does one service imply one serial source writer.

The previous ordinary mixed workload saved all eighty cases but failed public
readiness after180 seconds. That is not eighty-person capacity. This candidate
addresses a concrete dependency in preparation; it does not assign every
millisecond of that earlier failure to the dependency.

`Build.refresh` already derives public consumption from durable source
provenance. The private journal publisher independently retired and replaced
consumption for the same consumers. Public warm also waited for private replay.
The candidate makes source derivation the only publisher of shared facts and
keeps private usage in its separate cache and preparation job. Public frame
readiness no longer acknowledges or depends on that private debt.

The source preparation marker binds the full original head and source producer
in the same atomic index transaction. Generic index edits retire it, so a
replacement that strips consumption requires source reconstruction. A private
classifier change does not invalidate a public frame. Obsolete canonical
producers are rejected before opening their obsolete binding directory;
current-producer binding mismatches remain errors.

The focused controls use the same frozen original file-read and5/50 KB JSON
MCP observations with the parent and candidate. Public consumption agrees with
private trace consumption. An explicitly unfinished private replay removes
public edges with the old publisher, but leaves the candidate's public head
and facts unchanged. This is an API negative control, not evidence that the
same partial publication occurred in the ordinary eighty-client run.

Lean laws restrict private publication to complete usage, and ContractAudit
checks the connected public/private publishers, source marker, and worker
paths. Native tests exercise cold dispatch, public readiness with independent
private debt, exact shared facts, generic-replacement repair, and replay
retraction/recovery. They do not prove all IO, distributed ownership, or
eight-hour throughput.

The first paired attempt exposed the obsolete-producer opening order and
failed before candidate hooks. The first focused reporter also returned only
its ownership fields; it is retained as an incomplete report. Subsequent
reports require the complete schema and unchanged original heads. Compiler
failures remain in the guard evidence as well.

The corrected paired experiment rebuilds derived data before each arm's warm,
so the parent does not consume the candidate's incompatible physical caches.
The same original project and all32 head/page files remain byte-identical.
No original is regenerated and no seed model runs. Warm time is recorded
separately from hook time; these are not OS-cold latency measurements.

Three alternating matched pairs use the same fixed sixteen-owner project,
originals, question, MiniLM and settings. All twelve actual bodies are
byte-identical, contain both frozen original fields and leave all original
heads unchanged. Each invocation starts two fresh chats on one service lane.

The ordinary mixed workload keeps16 original owners, eighty clients,
5000-byte outputs, three preparation workers and the existing limits.
All80 writers succeed. Public readiness is reached in78,910 ms with16/16
sources and owner references ready, save queues empty, and preparation still
17 pending/3 active. This explicitly is not a completely drained background
system. The earlier180-second failure was a different generated workload;
the elapsed difference is not a matched causal effect size.

All eighty fresh readers are measured:62 deliver both frozen original fields
and finish successfully within30 seconds;18 fail at a worker/daemon deadline.
Semantic completion is9 and lexical completion53. Failure-inclusive hook
time is8,678–29,754 ms, median24,759 ms. The67 reader-scoped final service
observations have queue median18,744/max26,199 ms and work median725/max5,943 ms.
Do not mix writer phases into these distributions or call them full p99.
The capacity gate fails; increasing owners alone is not an evidenced fix.

A separate process reopens all82 original observations and checks exact
input/output, all80 posted cases published, no pending save sessions and
unchanged original heads. All18 guards finish with no owned survivors or
resource stops; maximum related RSS is3,067,408 KiB. The stop at3,670,016 KiB
and4 GiB ceiling are unchanged.

Private replay still imports foreign feeds and computes diagnostic consumption.
This candidate does not yet eliminate that duplication or all cross-owner
preparation. Certification, vector ranking, evidence selection, owner count,
workers, deadlines and resource bounds retain their existing contracts.

Next eliminate repeated foreign-feed/private trace preparation while keeping
private usage independent, and reduce the remaining per-query shared work
and queue time. Another unchanged eighty-client burst, a wider owner limit,
or retrieval-weight adjustment does not establish capacity.
