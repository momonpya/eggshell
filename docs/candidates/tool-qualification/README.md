# 小型判断器の未使用課題による事前検査

LFM2.5-1.2B-Instruct Q8を、LLVMとは無関係な固定3課題で検査し、不採用とした。製品のMiniLM、保存済みseed、現行配送を変更していない。

[公式のモデル説明](https://huggingface.co/LiquidAI/LFM2.5-1.2B-Instruct)と[tool呼出仕様](https://docs.liquid.ai/lfm/key-concepts/tool-use)を調べ、既存のnative engineがLFM2.5の形式を処理することをその固定sourceで確認した。モデルは公式GGUFのrevision/SHA/サイズを固定した。制御・読取・評価はLean、数値推論のみ既存のnative leafを使用した。

最初の3課題がすべて通った場合だけ、同じ3課題を独立contextで1回再確認する計画を生成前に固定した。正解のowner・必要箇所は評価器だけに渡し、判断器には渡していない。

| 課題 | 結果 |
| --- | --- |
| 決定と依存先の元観測 | 必要な原文を選び終えず、通常の回答を返して終了 |
| 日本語のMCP由来JSON | 未読receiptを使って選択しようとし、検査に拒否された後に通常回答で終了 |
| 長い原観測の末尾 | 選択操作は終了したが、無関係なownerを選んだ |

0/3のため2反復目とLLVM評価は行わず、同じ課題のprompt・model・制限を調整しない。普通の回答を許す`auto`呼出し設定の影響と、モデルの根拠選択能力は分けて扱う。この結果だけで、小型モデル一般や、厳密な構造化出力を使う方法まで否定しない。

[事前の条件](policy.json)、[独立した評価](assessment-1.json)、[操作の記録](transcript.json)、[不採用の判断](decision.json)を保存した。不採用モデルは削除済み。現行版の実配送は13/18のまま、本体採用・回答モデル追加は0。
