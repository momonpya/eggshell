# Frame reservation is not the sole cause of missing originals

Model-free diagnostic, no product change and no adoption. Two actual parent
hooks over the same retained sixteen-owner snapshot exactly match the previously
recorded bodies, including their missing fields. Source heads are unchanged.
The completed selection receipts are decoded independently, and replaying the
original inputs exactly reproduces both actual selected-unit lists.

An optimistic replay removes the entire fixed graph/status reservation. This
does **not** bound a real rendered packet and is not a deployable candidate.
Even under that optimistic condition, case0's original receives no selected
unit. Case28 obtains its first and last pieces, but not the complete5,000-byte
original. Therefore changing the fixed reservation alone cannot repair the
observed omissions. No budget, weight or deadline is changed.

UTF-8 bytes respectively. These are single diagnostics, not matched performance
or token results. Actual bodies are the unchanged retained
[case0](../worker-cpu/actual-case-0.json) and
[case28](../worker-cpu/actual-case-28.json).

survives later focus ordering. Case0 is admitted and hydrated, so repeating the
