# 引用された原文行を直接候補にする

**隔離した開発候補。必要コードの欠落は残る。最終採用・トークン改善の実証はまだない。**

同じ6段階の保存スナップショット・質問・原文検査で、引用区間と本当の推薦順位を接続した基準から、
引用された原文行を512文字窓に膨らませず直接候補にする処理だけを追加した。
有限の保存済み行を確認し、2048文字以内の原文区間にまとめ、元の段落・有界な前提範囲を保持する。
既存の窓候補と価値・順位・MiniLMのモデル/WindowCentroid採点、Exact・鮮度・権限・上限は変えない。
引用のグループを優先する別の段は追加していない。引用だけで元コードが必要十分とは主張しない。

2周目題材3のCompile境界が実配送に戻った。同じ全6段階検査の候補では合計の欠落数が最少だった。
残るのは題材1の警告（両周）、題材3のCompile境界（1周目）、no-output・ConstructJob（2周目）。
全12フックは段階内で本文バイト一致、最長21,200ms。通知だけの成功はなく、ACKとpublicationを検査した。
全24数値受領記録でsourceキャッシュ欠損/使用不能/source再埋め込み0。
原文・Unicode・範囲・出典・native権限を検査した試験、既存adapter、引用解析/投影、ContractAuditが成功。
途中の構文・試験fixtureの失敗も残し、実装の成功と混同していない。
最大aggregate RSSは2,963,840KiB。DB・質問・sourceの不変性を既存ハーネスで検査した。

欠落ゼロまでモデル測定を止める旧条件は、ユーザーの明示的な許可を受けて見直した。
配送漏れは記録したまま、固定した版で実際の回答・総トークンへの影響を測る探索的r0を認める。
配送漏れを合格扱いにする変更ではない。最終採用にはAGENTS.mdの同条件比較・固定複数反復・
総トークン改善・品質維持・期限内完了が引き続き必要。

この版のr0は開始前のディスクguardで止まり、モデル呼出し0・seed取得0。
続くユーザー指示により、未配送範囲の位置を添える候補へ進むため、未実行のpilot planをretireした。
新しい候補の本文やプロンプトを、旧候補のトークン結果と混ぜない。
差分の完全適用と変更後SHA、各本文、publication、失敗、資源記録は
[direct-citation-ranges-review.json](direct-citation-ranges-review.json)に保存した。
