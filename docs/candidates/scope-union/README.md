## Can one exact drop/add improve the existing objective?

The second diagnostic preserves the complete captured problem. It considers
every unselected offer paired with every selected offer: **477,468 pairs**,
of which **134,236** meet both wire limits. Shared nodes and cues count once;
an atom is refunded only when its final selected user is removed.

No strictly improving exchange is found. The result is independently checked
by rebuilding each deletion through the existing proof-carrying `Evaluation`
and evaluating all additions. The verifier accepts an upper bound equal to
the baseline's exact integer benefit. The kernel-checked theorem
`Exchange.all_exchanges_bounded` states that a successful verification bounds
every feasible one-drop/one-add exchange. This is a local-optimality result,
not a proof of global optimality or of question relevance.

The independent check is distinct from the counted fast search. Four small
cases compare the search against direct exhaustive cost/benefit recomputation:
shared source costs, duplicated features, shared cues and a byte-limit failure
despite a 100-digit weight. A falsely low bound is rejected. Checked improving
results also carry original-offer membership, exact shape, both limits and
strict benefit improvement; none is returned on the actual input.

**690 ms**. Both run inside `IO.lazyPure` between IO clock reads. The original
report's 0 ms pure-expression timing is retained as an invalid timing attempt.
The verified whole guard takes 7.053 s, peaks at 189,280 KiB and drains normally.
These measurements do not establish runtime, concurrency or p99 performance.

The three proof laws use only standard Lean axioms. The verified observer has
