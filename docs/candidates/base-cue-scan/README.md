# 基礎cueの照合量と、選択器単体の並行性

モデルを呼ばない診断と未採用の部品候補。通常製品 `0b0bbca8…` は変更していない。全フック80件の0/80を、部品の成功で置き換えない。関連RSSの上限5GB、保護停止4,358,524KiBを維持した。

過去の[range-postings](../../range-postings.md)が変えたのは束のbonus側だけだった。今回の対象は基礎offer側に残っているfamily投稿の走査であり、同じ旧変更の再投入ではない。元の「一つの区間に包含される」述語を保ち、空・逆順のpieceも別の候補キーで残す。区間の和集合による被覆へ意味を変えていない。

同じ固定snapshotと保存済み3queryを使い、元の全候補を一度復元した。[実入力の部品結果](component.json)は次のとおり。各3組、AB/BA/ABで測り、全単位で元のcue ID列が一致した。行・pieceの重複を勝手に落としていない。

| 問 | 単位 | 元の照合対象 | 範囲で絞った対象 | 元の時間 | 候補の時間 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1 | 7,238 | 4,328,002 | 128,712 | 95.5〜100.8ms | 10.2〜10.7ms |
| 2 | 8,285 | 5,076,129 | 150,163 | 124.2〜137.6ms | 13.8〜15.1ms |
| 3 | 7,433 | 4,507,173 | 134,117 | 107.0〜113.1ms | 11.4〜11.6ms |

各問16,790piece、元の採用IDは41,939 / 50,608 / 44,487件だった。空・逆順・接する区間・隙間・重なり・別familyの21コントロールも通った。索引の構築時間の欄は値を強制評価していないため無効と明示し、0msという性能値には使わない。上表は準備済み索引での照合であり、全フックの改善率ではない。実原文DBのSHAは変わっていない。

[一般定理と実関数への接続](proofs.json)では、任意の幅、任意のpiece/区間について、候補の元の値・順序・重複が全件filterと一致することをLeanで確認した。計測したnative sourceと同じ `rangeRows` へ定理を接続している。公理は `propext` / `Classical.choice` / `Quot.sound` のみ。通常製品のHandoffへはまだ接続していない。

さらに、変更していない通常の `selectView` を直接呼ぶ[診断](direct.json)を実施した。DB読出し、通信、埋め込み、フックを除き、3問の不変入力を一度保持して共有し、要求ごとにdedicated taskで実行した。

| 範囲 | 全件完了まで | 保存済みsource/generic選択キー |
| --- | ---: | --- |
| 直列3問 | 各484 / 676 / 541ms | 全問一致 |
| 4件同時 | 709ms | 4/4一致 |
| 16件同時 | 1,736ms | 16/16一致 |

関連RSS最大577,280KiB、原DB不変、残存processなし。比較したのはsourceKeysとgeneric unit IDで、ServiceChoiceの全メタデータではない。全フック16件の15,018msとは処理範囲が異なり、差の秒数を特定処理の時間として扱わない。選択器単体はこの入力で並行実行できたので、全体の遅延を選択器だけに帰して小変更を重ねる方針は採らない。次は実フックの前後にある準備・検証・受け渡しを、保存済みの段階記録と実呼出しから切り分ける。この約100msの部品変更だけで、無変更の80件を再実行しない。

部品のnative coreは製品と共通する238moduleすべてのsource/include bytesが一致した。[必要moduleの照合](native-sources.json)と[direct側](direct-sources.json)は部品用の検査であり、製品全体の閉包や80人実用化の証明ではない。製品用の厳しい全core照合は別の既存検査として維持する。

初回の補助buildはimportしたCLIのmain重複、direct補助buildは不要なInhabited要求を拒否した。初回のmodule名指定と証明用interface配置も訂正し、拒否記録を残した。いずれも製品の配送失敗やモデル試行には数えない。768MiBでの単体型検査はimport容量で終了し、1,536MiBで通った。実行用のnative閉包と原文は別に検査している。

終了した補助実行体・sourceコピー・proof interface・出力・生ログは[削除](cleanup.json)し、archiveを作らない。現行製品/監査器・比較元・元DB・project cache・MiniLM・必要な比較本文を保持する。回答モデル0、有料比較0/18。本体、README実績、releaseへの採用は未実施。
