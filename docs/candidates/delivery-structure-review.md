## 見直す単位

以前の実費用監査では、所有者ごとの最低候補をすべて積むと277,173文字で、
パケット上限120,000文字を超えた。必要条件を持つ候補は存在したが、最低候補の
集合や優先グループが先に枠を使った。最低枠を保証する証明は、この欠落を防がない。

次の設計対象は所有者の順番ではなく、**独立して選べる、出典付きの原文範囲**。

1. 数値・字句の既存順位が示す元の窓を、それぞれ必要な局所文脈と組にする。
   後ろの窓を選ぶために、先の窓の拡張をすべて買う必要をなくす。
2. 本文の断片と出典への辺を分ける。同じ原文を共有する場合も、各 Work/Outcome、
   元座標、source receipt と鮮度を残す。表示の共有から Union や Match は作らない。
   同一性が検証できない範囲は共有しない。
3. すでに選んだ範囲を除いた追加の質問被覆と、出典・グラフ枠込みの追加費用を
   一緒に比べる。所有者数、前回回答の長さ、到達可能な葉の数を需要にしない。
4. 必要な局所文脈を切らず、元断片だけを送る。文字数・UTF-8 byte・期限の上限は
   実際の最終パケットで検査する。どの質問にも必要十分な文脈を機械的に保証
   できるとは主張しない。

これはまだ実装・native 検証前の設計方向であり、改善・配送合格・採用の主張ではない。
既存の plan が独立範囲をどこまで表せるかと後段での欠落箇所を先に確定し、
同じ二つの優先順を入れ替えるだけの候補は作らない。検証用の期待コード・
行番号・題材・所有者名を実行時の選択規則へ持ち込まない。

## learned_index_lab の適用判断

ユーザー提示の [learned_index_lab](https://github.com/gilnett/learned_index_lab) と
[実装](https://github.com/gilnett/learned_index_lab/blob/main/src/pgm.rs) を確認した。
PGM は整列済みキーから配列位置を区分線形モデルで予測し、周辺を厳密探索する
データ構造。今回のように検索済みのコード範囲を後段で落とす問題の直接の修正には
ならないため、依存追加・移植・比較ベンチは行わない。

DB の不変な派生索引への将来的な適用余地はあるが、キー位置探索が支配的という
計測は今回ない。意味関連度には PGM の位置誤差上限に対応する保証もない。
近似で候補を提案して厳密な根拠で検査するという考え方は既存の推薦/認定分離と
整合するが、それを理由にこの索引を配送の修正と称して導入しない。
