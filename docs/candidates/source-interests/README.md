# Fulfil exact captured inputs through shared preparation

Isolated continuation of [prepared-cuts](../prepared-cuts/README.md), not adopted.
One logical project retains multiple independent original append owners.
Original publication/project code and the three-worker bounded preparation
scheduler are unchanged. This is not eighty-person capacity or token evidence.

## Request and preparation contract

Every automatic turn captures its complete original inventory, including absent
raw sources, and requester-private usage roots before testing shared readiness.
An unavailable ready frame cannot erase those original heads. Private usage
that advances or appears later cannot replace the captured root or absence.
These headers remain private turn/operation metadata.

The foreground registers the existing local provider/owner configuration, then
submits a full source-head interest to the shared service. The service resolves
only that checked private configuration. It validates the original parent chain,
not just the reader's extent bounds, and gives distinct heads distinct job keys.
Identical pending interests coalesce. No per-query registry file, question or
private usage payload is added to the preparation queue.

Workers restore the requested head and run ordinary background preparation.
They do not consume or delete newer source tickets while preparing an old cut.
A ready input frame is published only after journal replay reports completion.
Historical readiness uses that source-bound frame, rather than the installation's
latest replay checkpoint. Newer completed roots remain readable.

The waiter performs metadata reads and sleeps with a bounded polling interval;
it does not warm or reconstruct the corpus. Queue rejection remains retryable
within the original cutoff. Semantic preparation waits use the semantic cutoff,
leaving the original hook deadline for exact-cut lexical fallback. Read-only
project interests prepare user overlays, never grant an original writer lease.
The operation queue checks the complete original and private boundary again.

Explicit captured absence can pass downstream selection only with its matching
full head inventory. An unbound omitted source remains an error. Recommendation,
e-class equality, completion authority, selection weights and delivery budgets
are unchanged.

`InputBoundary` contains the actual pure predicates used by rooted input capture
and operation validation. Their small proof dependency excludes the numerical
and source-index implementation hashes. ContractAudit checks those runtime
connections, original reader restoration and the absence of foreground warm.

Helper `a14518e2…` uses the [Lean checker](../../../tools/research/SourceInterestChecks.lean).
It publishes and prepares A0/B0, captures unprepared A1/B1, then publishes and
prepares A2/B2 first. The original A1/B1 responses are checked in the complete
eight-owner original domain before delivery. The checker never calls historical
warm: the normal `deliverForWork` path submits the exact interests, waits for
background completion, enters the operation queue, extracts and offers the body.

Both runs observe two simultaneous preparation workers. Each has one

The read-only case checks that its lexical inputs use user storage.
[Write body](write-body.txt), [read-only body](read-body.txt).

Private A usage really advances after capture, and private B usage really
appears after captured absence. The completed operation retains the older A
root and B absence. Queue validation rejects substitution even when the ready
frame is removed. The tests also reject a foreign head, an unpublished extent,
and a fabricated root that passes extent-only retention but is not in the
original parent chain. They preserve raw DB absence after that path is created,
and continue rejecting an omitted source with no explicit captured boundary.
A [fresh process](restored.txt) restores the final write run's exact roots and
returns byte-identical actual delivery.

These are tiny synthetic lexical conditions, not a paired speedup, numerical
query, token result, practical 98% result or eighty-client workload. Earlier
positive diagnostics before proof isolation are retained separately in
[prior-write.json](prior-write.json) and [prior-read-only.json](prior-read-only.json);
they are not pooled into the final executable's results.

[Seven kernel laws](laws.txt) prove complete original/input inventories and
exact private roots, and reject changed private roots. Dependencies are only
`propext` and `Quot.sound`. The final native build includes ordinary ContractAudit
and checks the actual runtime wrappers call these pure predicates. These are
structural guarantees, not proofs of native IO or sustained capacity.
[Failures](negative-checks.json) retain compiler errors, the raw-absence bug,
an incorrect fixture assumption that initial warm had not created B usage,
and two rejected proof runs hitting the unchanged 1 GiB proof-process limit.
The proof dependencies were isolated; no memory ceiling was increased.

[Resource records](resources.json) show aggregate sampled peak 2,844,160 KiB
including builds, no aggregate guard trip and no owned survivors. This is not
an eighty-client RSS measurement. The 3.5 GiB stop/4 GiB ceiling and 2 GiB disk
floor remain. [Identity](result.json) records the unchanged original publication,
project and scheduler sources, zero encoder/answering-model calls and no adoption.
[Retirement](retired-helpers.json) deletes nine superseded stopped executables,

## Remaining gates

Exact interests currently survive their waiter and finish as useful background
cache work. Last-waiter cancellation/expiry, unavailable-source retirement and
saturation recovery still need explicit lifecycle/accounting before sustained
use. Catalogue/extent compaction leases, mixed cache namespaces, full cross-project
dependency closure, actual numerical execution and multi-host/NAS durability
remain open. The small lexical checks cannot establish an eighty-person,
eight-hour workload, p99 below 30 seconds, practical 98% evidence delivery or
matched total-token/quality adoption. Paid comparisons remain 0/18.

Ended experiment DB/cache/raw logs and superseded executables are deleted after
compact evidence is extracted. No archive is created. Current build inputs,
required numerical dependencies and protected originals are retained.

[Cleanup](cleanup.json) removes 3,054,047 apparent bytes of finished fixture
DB/cache/raw logs, in addition to the retired helpers above, without archiving.
[Protected-original checks](protected-after.txt) pass after deletion.
