# 全文を失わない採点入力と配送量の効果試験

隔離した研究用候補。今回の小型rerankerでは必要根拠を選べず、不採用。本体のvector、WorkGraph、3辺、認定、MiniLM、登録フックを変更していない。

以前の[点別採点](../grounded-judgment/README.md)は、判断対象の短片の和集合にも必要根拠が11/18しかなかった。今回は同じ受理済みsnapshotの58原記録を、既存の原文読取と同じ2,400文字のページへ分け、末尾まで保持した。271個の物理ページに272個の原観測参照を持たせ、同じ本文でもWorkと原文座標を失わない。ツール名や出力形式で除外せず、質問・正解・配送結果を入力の準備に使わない。

[入力検査](report.json)では573,377文字を復元し、全18項目が採点対象に存在することを確認した。準備は88msだったが、これはこの固定入力の準備時間であり、フック時間や大規模共有時の測定ではない。原文指紋は文書ごとに一度だけ計算し、ページごとに全文を再ハッシュしない。欠落・重複・範囲外の採点IDを拒否する。Leanの[kernel検査](proofs.txt)はページ境界、全IDの被覆、原観測の同一性を扱う。関連性や98%配送の証明ではない。

同じQwen3-Reranker-0.6B Q8、同じ3問、同じllama.cpp b12110を使った。モデルSHAは`22c9979ce4fbcdc5acdc310c6641c32797eff1aa980b8f7a2db8a8ea23429a48`。各入力は記録された操作と完全な原文ページで、全ページを採点する。最初の30秒要求は応答なしで失敗し、終了を確認した。利用者の指示を受けて診断用期限だけを120秒に変更し、全3問の入力を推論前に固定した。モデル、質問、ページ幅、採点promptを結果に合わせて変更していない。

## 選択された原文

各問271個すべての点数が返り、時間は115,957 / 115,216 / 118,674msだった。順位順に完全なページを入れ、原典の指紋・Work・操作は文書ごとに一度だけ付ける。実際に描画したJSONの文字数とbytesで予算を検査し、途中切断しない。次の全5枠で本文を作り終えた後に、凍結済みの正解を開いて照合した。

| 事前固定した文字枠 | 題材1 | 題材2 | 題材3 | 合計 |
| --- | --- | --- | --- | --- |
| 8,000 | 0/5 | 0/7 | 1/6 | 1/18 |
| 16,000 | 0/5 | 1/7 | 2/6 | 3/18 |
| 32,000 | 0/5 | 1/7 | 2/6 | 3/18 |
| 64,000 | 1/5 | 3/7 | 2/6 | 6/18 |
| 120,000 | 1/5 | 6/7 | 5/6 | 12/18 |

この表は[本文案の原文照合](effects.json)であり、実フック配送ではない。現行の実配送13/18、引用範囲の親候補15/18に対して、改善を支持する結果は得られなかった。配送量を減らしながら必要根拠を保つ目的にも達していない。本体接続、回答モデル、README実績への採用は行わない。単独の点別採点結果なので、既存のvector・WorkGraph・3辺全体の限界や小型モデル一般の不可能性を結論しない。

質問を「日本の首都」と「重力」に変える別の小さな対照では、それぞれ対応する原文が1位になった。質問が数値サービスに渡っていないという説明は支持されなかった。題材1では過去回答や短い計画通知が上位に来ているが、その原因が操作のprefix、原文の内容、採点モデルの性質のどれかは切り分けていない。直ちにそれらを削る修正や、同じ3問への閾値・重み調整へ進まない。

## 予算と選択を分ける診断

全5枠の選択と本文が以前の結果と完全一致することを検査した後、正解を使う診断専用の組合せも作った。同じページを選ぶだけで、全項目は次の費用に収まった。

| 題材 | 原文を含む項目 | 出典付き本文の文字数・bytes |
| --- | --- | --- |
| 1 | 5/5 | 12,584 |
| 2 | 7/7 | 21,159 |
| 3 | 6/6 | 21,097 |

これは最小解の主張でも、実装が自力で選べた結果でもない。正解は採点器・上記5枠・フックへ渡していない。この原文単位でも予算内に全根拠が入るという反例であり、今回の欠落を枠不足では説明できない。必要原文の保持と、必要なものを選ぶ能力を区別する。

成功した全頁採点は計873,868入力token、質問交換の対照は529token、既知の合計874,397token。初回30秒失敗の全消費は不明なので、この合計に含められず、無料とは扱わない。生成による回答はなく、新seed取得費用0、回答モデルの呼出0、fresh比総token削減率は未測定。文字数の差をtoken削減率と呼ばない。

数値試験の関連RSS標本最大1,354,416KiB。全guardの終了、全モデルサービスのpipe・IPC終了、残存processなしを確認した。単一slotの診断であり、16/80並行や実フック30秒の合格ではない。[実行検証](verification.json)、[数値応答](numerical.json)、[sourceとnative closure](executed.json)を残した。終了したモデル・source/build・生成入力等1,247項目、1,268,109,687論理bytesを[削除](cleanup.json)し、archiveは作らなかった。受理済み原典、保持製品2つのSHAとnative closureは不変。

次は既存の失敗案を含め、原文を失わない入力と「質問に似ている」点数を分離して扱う。新しい選択案は、WorkGraphの支持・依存構造を省いた点別類似度の繰返しにせず、未使用の反証課題と停止規則を先に固定する。今回の3問へモデル・prompt・予算を合わせ直して成功値を作らない。
