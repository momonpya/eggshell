# 引用の範囲と生成元を、保存済み原文の候補へ渡す

研究用plannerの入力adapterを、実フックが使った質問・推薦順位・グラフ・原文へ接続した。
自動選択規則や配送本文の変更はまだない。本体、README実績、回答モデルのベンチへは未採用。

## 実際の入力を保持する

診断版の新しいtraceには、実際のfocus質問、引用元の所有者とnomination順位、
入場済み観測の原文と依存記録、nativeのAll経路を記録した。
元のnomination順位はfamily表示順と異なるため、後者から推測しない。
1周目題材1は引用元1件、2周目題材3は6件だった。質問は既存処理による原文suffixのまま543/694文字。
質問の書き換え、モデルの変更、引用先のURL/ファイルの読み取り、正解を使った候補追加はしていない。

両native hookの本文は凍結候補とバイト一致し、候補・費用・被覆・選択集合も前の診断と完全一致した。
11.578/18.397秒で完了。元snapshotは不変で、別の出版監査もauthoritative graph・root・Unionの保持を確認した。
traceだけを増やした診断の成功であり、配送漏れの解消ではない。

## 原文と出典を壊さない対応付け

[citation_bridge.py](../../tools/research/citation_bridge.py)は引用の始点・終点・引用元順位を保持する。
Markdown表示の範囲は、完全な既知pathを持つリンク先と開始行が一致するときだけ使い、矛盾は明示する。
GitHub形式の行範囲と、URLエスケープされたpathにも対応する。リンクは一切開かない。

[project_citations.py](../../tools/research/project_citations.py)は実際のAll経路で到達した観測だけを使う。
各観測のfile fingerprintと、literalな`nl -ba PATH | sed -n RANGE`の記録を参照し、
保存済み本文の番号付き行を元のJSON scalarの文字座標へ戻す。ファイル本文を外から取り込まない。
Unicode、surrogate pair、先頭の警告、途中の切り詰めを扱い、番号の衝突や未対応形式は不足として残す。
plain sedの出力に固定offsetを当てて行番号を捏造しない。
Workのメタデータはhashを記録した実験の文書inventoryから受け取るIO境界であり、外部shellの意味論を証明するものではない。
対応付けは推薦の手掛かりだけで、鮮度、WorkのUnion、completed、意味的な正しさの権限を作らない。

| 入力 | 引用 | 観測への対応 | 引用全体が保存済み | 元の局所前提を持つ候補への束縛 |
| --- | ---: | ---: | ---: | ---: |
| 1周目・題材1 | 38 | 39 | 34 | 184候補 |
| 2周目・題材3 | 61 | 60 | 51 | 387候補 |

一つの引用が複数の観測にある場合と、対応できない引用があるため、各列は一対一ではない。
コピー数をそのまま価値に足す設計にはしない。
未対応の命令列、行番号のない観測、完全に保存されていない引用を、成功として隠さず出力する。

## 全引用を必須にしない

長い引用範囲のすべてを一候補へ要求すると、必要な短いコードが存在するのに使えなくなる。
2周目題材3のConstructJobにはまさにこの差がある。過去回答の引用全体は保存されていないが、
必要な呼出し行と、その局所前提を持つ完全な候補はある。

そこで、引用元の順位を、引用範囲内の元の検索cueと、そのcueの完全な候補へ対応付ける。
単なる文脈拡張が引用に触れただけでは、新しい価値を得ない。
引用の順位、原文行、query/referenceそれぞれの元の位置と順位を混ぜずに記録する。
必要な元コードは評価専用の別処理で後から照合し、入力adapterは正解リストを読まない。

この事後評価では、2周目題材3の未配送5項目すべてに、原文を完全に含む候補への手掛かりがある。
HLSLの完全な分岐へはnomination順位0/3から、Compile打切り、末尾-x警告、出力Action打切り、
ConstructJobへは順位0から到達した。これらは自動選択や新しい配送本文の合格ではない。
題材1の未配送警告コードには引用の入力がない。引用だけでなく、現在質問の独立した数値検索も維持する必要がある。

parserとadapter、既存の研究用選択器を合わせた15試験が成功した。
引用の範囲/順位、矛盾、Unicode原文座標、曖昧な複数ファイル、切り詰め、巨大な行番号、
未対応命令、到達していない観測の排除、文脈拡張への誤った価値伝達を検査した。
ビルド最大RSS2,800,288 KiB、native 1,413,840 KiB、射影107,664 KiB。監視停止なし。
全記録は[citation-plan-input-review.json](citation-plan-input-review.json)に参照とSHAを保存する。

次は、この候補に束縛された手掛かりと現在質問の数値入力を、重複で増えない論点別の目的へつなぐ。
引用や所有者の全体予約、全引用の完全配送を一律に要求する方式には戻さない。
新selectorは隔離したまま題材1から全6段階の実本文を検査し、その後に固定モデルのr0へ進む。
