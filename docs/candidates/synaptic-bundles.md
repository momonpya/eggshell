# 関係が要求する原文の組を選択まで保つ

隔離して実装・検証する候補。採用・配送改善・トークン改善は未確認。
前回の単一所有者内の区間追加とは異なり、複数所有者の原文を含む関係を選択器まで運ぶ。

## 測定前に固定する規則

- 数値検索と既存の直接引用の価値をbase、追加のシナプスによる価値の差をbonusとする。
  同じ原文位置の最大価値は従来どおりで、`base + (max base graph - base) = max base graph`を使う。
  順位係数や総予算、MiniLM、配送プロンプトを調整しない。
- baseは従来の元観測候補で満たせる。bonusは、一つの段落の共引用、一つの導出証拠、
  一つの有効な利用eventが要求する保存済み原文を全て持つ選択肢だけが満たせる。
- 回答と段落の共引用を区別して有界索引から列挙する。途中で切れた探索の部分結果へ価値を付けない。
  `omitted_then_read`優先・通常再読や指紋変更の除外・質問digestの私有境界は維持する。
- 関係の各範囲は、同じファイル指紋を持つ既存の観測と元scalar行へ束縛する。
  一つでも対応できない範囲があれば、その関係からのbonusを認めない。
- 同じ所有者内で共通する原文や出典ノードの費用は既存の共有費用で数える。異なる元観測への束縛は保つ。
  一つの範囲に複数の元観測がある場合は、関係内の実際の追加費用が小さい候補を決定的に選ぶ。
  正解リスト、質問名、特定のパス、試行結果をこの選択へ渡さない。
- 従来の候補は残し、完全な原文区間の候補を追加する。単独行の候補を消して置換しない。
  関係のbonusと、原文を現在の数値検索が独立に推薦する価値を混同しない。
- 選択した関係を元のunit列へ展開してから描画する。
  bonusを得た関係の全unitが展開結果へ含まれることと、展開前後の共有費用の一致をLeanで検査する。
  全体の文字数・UTF-8 bytesと認定由来の制御は従来の最後の検査も通す。

これは推薦の価値を与える条件である。引用の正しさ、ツールの意味的な消費、回答の正しさを証明しない。
Match・Union・completedを生成せず、「推薦と認定の分離」は保持する。

## 検証順

まず複数所有者の関係、片方だけの配送、未保存範囲、指紋不一致、独立した数値推薦、
重複関係、共有費用、両予算をLeanの小さなfixtureで確認する。
次に実Pre/Post/Stop・新規チャットの実stdout・受領記録とContractAuditを検査する。
凍結後に同じ6snapshot・質問を題材1から各2チャットで検査し、欠落と未保存を別々に数える。
この結果に合わせて係数を調整しない。モデル測定と最終採用の条件はGOAL.md/AGENTS.mdに従う。
