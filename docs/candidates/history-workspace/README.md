# 読んだ原文を失わない履歴判断器

隔離候補。製品の検索・保存・認定、MiniLM、現行の配送は変更していない。

旧判断器は次の判断に最新のtool応答と既読範囲の先頭80文字だけを渡し、同じページの再読も読取上限へ加算していた。また、toolで選択を終える要求に対して`tool_choice: auto`を使っていた。これらが以前の失敗の原因だったとは、まだ断定しない。

候補は固定snapshotに結び付くLeanの作業状態を持つ。開いた原文は全文を一度ずつモデルに見せ、同じページは同じreceiptと読取費用を再利用する。全文がモデルの文脈上限へ収まらない場合は、黙って切り捨てずに失敗を記録する。原文を読めることと、必要な原文を正しく選べることは別である。

判断は検索・一覧・既存辺の参照・原文読取・読了原文の選択・根拠なしの6操作に限定したJSONにする。普通の技術回答を根拠選択の完了として受理しない。最後の判断は選択か根拠なしに限定する。未読・範囲外・別snapshot・同じbatchの未返却read・書込を拒否する。Unionやcompletedを作る権限はない。

llama.cpp b12110の[JSON schema処理](https://github.com/ggml-org/llama.cpp/blob/b12110/tools/server/server-common.cpp)と[入力token計数処理](https://github.com/ggml-org/llama.cpp/blob/b12110/tools/server/server-context.cpp)を確認した。生成前に同じ要求をnativeの計数APIへ渡し、入力と出力上限の合計が8,192token以内であること、実usageの入力数と計数が一致することを検査する。判断回数8、25秒、原文読取16,000文字、選択12,000文字、出力384tokenは旧制御と同じ。

[native検査](checks.json)は成功した。全文・Unicode・JSONの保持、再読のID/費用再利用、読取権限と上限、失敗時に原文を切り捨てないことを確認した。[kernel検査](proofs.txt)は原文座標と状態の不変条件を扱い、関連性や98%配送を証明するものではない。

固定モデルLFM2.5-1.2B-Instruct Q8と同じnative runtimeを使い、未使用の3課題を旧制御・候補各2回で比較した。順序は旧1→候補1→候補2→旧2。実行イメージの版の違い、日本語MCPの環境違い、依存先の原文と以前に開いた前提の保持を検査した。正解は評価器だけに渡した。全4回を実施し、失敗分も入力＋出力tokenへ含めた。候補が両反復で全3課題を通らなければLLVM評価に進まず、同じ課題へmodel/prompt/制限を合わせない条件を事前固定した。

## 比較結果：不採用

| 課題 | 旧制御：1回目 / 2回目 | 候補：1回目 / 2回目 | 候補の問題 |
| --- | --- | --- | --- |
| 実行イメージの版 | 不合格 / 不合格 | 不合格 / 不合格 | 無関係なサービスの観測を選択 |
| 日本語MCPの環境 | 不合格 / 不合格 | 不合格 / 不合格 | productionに対しstagingを選択 |
| 依存先と以前の前提 | 不合格 / 不合格 | 不合格 / 不合格 | 最初の前提だけを選択し、依存先の条件を欠落 |

旧制御は6回とも通常回答などで選択操作を完了しなかった。候補は6回とも選択操作を終えたが、正しい根拠の選択は0/6。候補は最初に複数原文を読み、その後は選択と他の操作を混在させる判断を繰り返し、拒否された。必須tool名が記録にあることは、正しい依存辺をたどった証拠ではない。本文保持と構造化出力を同時に変えた比較なので、個別の効果も分離していない。

候補の判断時間は16,407〜25,037ms。1回は事前の25,000ms上限を37ms超え、独立評価器が不合格にした。生成応答の捕捉前に通信期限を秒単位に切り上げる研究用制御であり、`finished=true`だけで期限内成功と判断しない。製品の30秒以内を測ったものではない。

旧制御は各反復6,399token、候補は各反復26,634token、全試行の入力＋出力は66,066token。cached inputと失敗した生成を含め、全12課題の全生成要求にusageがあることを確認した。これはローカル判断器の消費であり、回答モデルのfresh比削減率ではない。新しいseed取得費用は0。関連RSS標本の最大は1,802,960KiB、保護停止0、全4モデルサービスのpipe/IPC終了と残存process0を確認した。

[独立評価](qualification-assessment.json)、[凍結条件と実行検証](verification.json)、[原文・質問・正解と全結果](transcripts.json)を保存した。この構成は不採用。LLVMや回答モデルは呼ばず、同じ課題で調整を繰り返さない。この結果で小型モデル一般や、本体のvector/WorkGraph/3辺の限界を結論しない。

終了した実験用source/build/cache/modelは1,431項目、1,738,515,983論理bytesを[削除](cleanup.json)した。不要になった旧seedの派生cacheも1,843項目、737,299,574論理bytesを削除した。archiveは作らず、原典DB、履歴、保持製品のSHAとnative closureを確認した。再利用可能なLeanの読取契約と研究用controller、検査、必要な実行記録だけを残す。

この検査は実フックの配送や回答モデルの両周ではない。現行13/18、引用範囲の親候補15/18、回答両周0/6、matched総token/品質比較0/18、本体採用0と区別する。
