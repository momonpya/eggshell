# 判断器が履歴を自律的に確認するための読取契約

Leanで、固定project snapshotに対する履歴検索、原文ページの読み取り、既存の依存辺の参照、読了範囲からの根拠選択を実装した。現行製品への接続・採用はしていない。

履歴は一度準備した不変Storeとして保持する。読取位置と根拠IDは問い合わせごとの状態に置く。モデルに本文を際限なく積まず、現在のtool応答と確認済み範囲の一覧を渡す。検索のpreviewは読了の証拠にしない。未読範囲、別の読取ID、同一batch内でまだ返却していないreadからの選択、書き込み操作を拒否する。選択値は要約ではなく、元owner・snapshot・原文文字座標と本文に結び付く。認定・Union・completedを作る権限はない。

`HistoryAccess.authorized_within_read`はLean kernelで公理なしと確認した。これは選択範囲が確認した原文の内側にあるという性質であり、関連性や必要な根拠の完全配送の証明ではない。実行時のUnicode/任意テキスト、未読/範囲外/不明ID/書込拒否の検査も通った。

## 数値結果と不採用の判断

推論のみllama.cpp b12110のnative実行体を使い、制御・検索・読取・原文監査はLeanで実装した。小型生成モデルはQwen3.5-0.8B Q8、モデル833,592,096 bytesのSHAを固定した。[公式モデル](https://huggingface.co/Qwen/Qwen3.5-0.8B)、[固定した変換元](https://huggingface.co/ggml-org/Qwen3.5-0.8B-GGUF/tree/004fd086eccea9f7cf867aa07ba328773beef81d)、[native tool呼出仕様](https://github.com/ggml-org/llama.cpp/blob/b12110/docs/function-calling.md)を確認した。MiniLMと保持製品は変更していない。

初期の合成3記録では、モデルが検索→原文を開く→選択を自律的に行い、必要な条件式を含む本文を4,131msで返した。ただし無関係な1記録も選んでおり、精度の合格ではない。

同じ受理済みLLVM seedの58記録と、出版済み29,896 Factを固定して題材1/2/3を試した。正解リストはモデルに渡していない。段階の失敗を隠さず、操作APIの修正後も全3問を最初から検査した。

| 段階 | 題材1/2/3の判断完了 | 観測した問題 |
| --- | --- | --- |
| 初期 | 0/3 | 大きなlengthを繰り返し要求し、拒否から回復しない |
| 自動ページ読取 | 0/3 | 本文の会話への累積でcontext上限超過、または決定数を消費 |
| 保持履歴とモデル文脈を分離 | 0/3 | 読取を続け、選択しない |
| 問い合わせと状態を同一入力へ統合、残決定数を明示 | 0/3 | 同じ末尾付近のread/範囲外拒否を繰り返し、選択しない |

最後は7,899/7,969/7,618ms、選択原文0/5・0/7・0/6で未達。guardの正常終了は取得器が記録を閉じたという意味で、モデルの判断成功ではない。独立したnative監査でも未選択を確認した。全試行で返されたusage合計は278,475入力＋出力tokenで、cached入力と失敗段階の完了済み要求を含む。usageのない拒否要求を含めた完全な消費会計とは主張しない。最後の関連RSS標本最大は3,283,104KiB、5GB制限/保護線は変更していない。

この0.8B構成は不採用。同じ3問でprompt・窓幅・決定数を再調整しない。判断器に履歴確認を許す操作基盤と、この構成が実問で必要な根拠を選べるかは別である。

## 検証の境界と次の条件

この試作の検索は事前作成した字句索引であり、本体のvector routerを接続した比較ではない。隣接出力には消費2,577件・支持4,260件が現れたが、共引用/利用の完全な輸送は未証明。全3辺や本体全体の有効性をこの結果だけで否定しない。80人/16並行、複数DB、実hook、98%、総token改善を達成したとは扱わない。

引き継ぐのは読取契約と追跡・原文監査である。次の判断器は、未使用の小さなtool課題で検索・打切り・選択の能力を先に確かめ、本体のvector/WorkGraph/シナプス候補を使う経路に接続する。同じ3問の再調整や、本文を読み続けるだけの処理を本体へ入れない。現行の実配送13/18、回答両周0/6、matched総token/品質比較0/18、採用0を維持する。

終了したDB派生物、モデル、source/build/run cacheは削除し、archiveは作らなかった。保持製品347 native objectと候補の各entryの整合、原典・seed/履歴の前後SHA一致を確認した。一回限りの修復/終了制御コードも削除し、再利用するLeanの読取契約・数値呼出・監査だけを残した。実行記録はファイルごとのSHAと共に少数のJSONへ整理した。判定は[decision.json](decision.json)、原文監査は[assessment.json](assessment.json)、失敗を含む結果は[experiments.json](experiments.json)、[削除記録](cleanup.json)を参照。
