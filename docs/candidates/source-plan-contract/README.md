mismatch, but does not improve the fixed LLVM evidence result. The current
product and global installation are unchanged. No answering model was called.

## Why the producer-window hypothesis is closed

Both native diagnostics are bound by SHA-256 and byte equality to the ordinary
first-topic body; they are not extra hook latency samples. The actual selector
has 4,145 units instead of the parent's 8,329 and selects 107 units. It still
omits the required cache declaration, function boundary and other evidence.

The canonical-body audit compares every displayed row with pinned original
bytes. Of 1,871 displayed rows, 1,866 belong to at least one completely
displayed published unit. Only Driver.cpp:1856–1860 lack that witness; these
five rows do not explain the missing required ranges. In particular, the
complete selected producer unit covering `if (!TC)` contains **7105–7116**.
The observed adjacent lines 7101 and 7104 are absent. Retaining a whole raw
producer window therefore does not preserve the necessary source context.

`diagnostics.json`, under the `signals/diagnostic/selection.json` key, retains
the actual finite selection input and source-node witness. The integer-only
Lean audit finds:

- 16,714 cue pieces, all with positive base weight;
- 293 pieces where graph hints increase the weight, yielding 82 distinct
  graph bonuses after canonical sharing;
- 347 prepared bundles: 134 with a positive graph bonus and 213 without;
- one selected bundle;
- direct graph bonuses on the missing **7101 and 7104** rows themselves.

Thus neither missing graph connections, zero graph value everywhere, nor the
five context-unit bypasses alone explain the loss. `graphOffers` in the audit
counts offers that contain the row and any positive graph cue; it does not
assert that the cue belongs to that row. `hasDirectGraphBonus` separately
compares the maximum base and total coefficients for the row itself.

No weights, window widths, reservations, budgets or thresholds were fitted.
Do not repeat this same whole-producer-window candidate or treat the source
contract repair as a recall improvement. The next design must address the
selection of a recorded Work's dependencies; having each row available as an
independent scored alternative has not delivered its required evidence.
