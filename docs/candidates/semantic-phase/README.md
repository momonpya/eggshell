# Fixed-snapshot request trace

The Lean controller invokes a frozen actual executable on the retained project
snapshot, explicitly warms its derived inputs, and records two new-chat requests
through the ordinary hook client. It checks the actual original fields, received
stdout identities and all sixteen original heads, then closes the services.
Existing stage traces and optional service profiles remain diagnostic overhead,
not an uninstrumented latency result. No answering model is called.

The baseline and service-oracle traces, and the six alternating trials, are
sealed in[local-selection/evidence.json](../local-selection/evidence.json).
See the[results and scope](../local-selection/README.md) before using any timing.
Ended private roots and logs are removed after recording; the original fixed
snapshot is still an active comparison input.
