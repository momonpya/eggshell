# Published producer windows: rejected isolated candidate

The [real LLVM parent](../source-snapshot/llvm/README.md) loses original rows
after admitting their owner. This candidate preserves the numerical producer's
actual window-to-original-row membership at publication. Graph-derived groups
retain a published containing window instead of bypassing it with row fragments.
It does not change the model, ranking weights, authority or 120,000-character
delivery budget. It is **not adopted** and changes no installed product.

## What was checked

The [native audit](native.json) verifies 348 selected objects and the
[source comparison](sources.json) permits exactly two existing metadata modules,
one added pure module, and their exact embedded source bytes. The complete
observer imports the same product core with [unchanged common sources](observer-sources.json).
The [kernel audit](proofs.json) checks original-row eligibility, bounded record
retention, a containing prerequisite unit, unchanged row identity and exact
rendering costs, using standard axioms only. It also checks the actual publication
connections. These laws do not establish relevance or a 98% delivery rate.

[Native component checks](checks.json) exercise ten original row groups, four
producer windows, serialization, two federated source DBs, rejection of five
invalid metadata/scope cases, and a missing federated row. They pass. Initial
compiler and observer refusals remain recorded; none is counted as a successful
test. No answering model was called.

## Actual LLVM result

Before warm or retrieval, the candidate independently freezes the same **4/7/5**
available evidence units as the parent. [The native head, source-file hashes and
complete frozen evidence match exactly](llvm/fixed-inputs.json). The source is
the existing incomplete, unaccepted corpus; this is not an accepted seed or an
answering-model benchmark. Both passes use independent fresh chats and add no
answer history.

Initial `egg warm --shared` succeeds in **136.259 s**. Discovery and focus each
have 2,038/2,038 valid windows, zero missing and zero invalid entries. This is
cold preparation time, not hook latency.

All six requests are rejected **before search** with
`original view exceeds its query budget`; semantic state is `notRequested`.
The 356-byte responses contain no required original evidence. Thus **0/32**
appearances are delivered, versus the parent's **16/32**. The short failure
responses are not successful fast retrieval. Actual callbacks and bodies are
retained losslessly in [callbacks.json](llvm/callbacks.json) and [bodies.json](llvm/bodies.json).

The candidate also changes `OwnerReady.bytes` from descriptor-plus-focus to the
full stored metadata. The unchanged shared-view admission reserves
`65536 + 32 * countedBytes + leaseCharge` against 128 MiB. This admission failure
prevents measuring the proposed grouping's selection effect; it is not evidence
that the grouping improves or worsens ranking. Limits are not raised, and window
widths, owner reservations, weights and budgets are not fitted after the failure.
The next diagnosis must distinguish shared resident metadata from private query
references and measure which bytes drive admission, before another selection trial.

The [original guard](llvm/summary.json) finishes normally with no owned processes;
sampled related peak is 2,183,200 KiB. All three services acknowledge normal exit
and remove their endpoints. Source and captured bytes are unchanged. A successful
observer exit means the negative measurement completed, not that delivery passed.

## Retained parent and cleanup

The parent remains the implementation that passed **two DBs, up to fourteen mixed
clients**, new/existing/resumed contexts, interruption/restart, delayed/duplicate
events, project switching and four growth waves: 72/72 semantic queries,
1,476/1,476 required appearances including retained context, 429 successful hooks,
maximum hook 2.327 s. This is a small direct-hook fixture, not actual UI sessions,
large-corpus recall or an 80-person deployment.

The failed candidate's DBs, caches, copied sources, installation and builds are
[deleted without archives](cleanup.json): 7,966 files / 1,435,010,126 logical bytes.
All 355 protected native hashes agree before and after deletion; the retained
[347-object parent still has consistent inputs](parent-after-cleanup.json).
The original LLVM DB, model and current parent remain. Only compact evidence,
the isolated patch, pure module and check sources are retained. Adoption remains
**0**, accepted LLVM answering stages **0/6**, matched total-token/quality
comparisons **0/18**. This turn records progress and a rejection; the goal remains active.
