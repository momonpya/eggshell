# Captured native sources and repeated mixed-client checks

This isolated candidate extends the [direct project connection](../delegated-connection/README.md).
It preserves an existing native DB as a sealed read input, without recreating its
work graph, original observations, source identity or authority. The product and
global installation remain unchanged. Adoption and paid comparisons remain zero.

## Existing sources join the project reader without fabricated history

`egg snapshot DB TARGET` copies exactly the committed extent through a pinned
file descriptor into a fresh read-only project. Later appends and later pathname
changes cannot change the captured input. A checked project manifest is the
single source of cache membership; the duplicate `cache-scope` record is removed.
Managed projects retain their original history checks. Captured sources accept
only their exact registered heads and cannot acquire a publisher Owner or grant.
The wrapper does not assert or invent historical project dependencies.

`egg warm --shared PATH` explicitly requests preparation of a host-owned shared
derived cache. It requires database-local cache targets and grants no writes to
the original source. Default read-only preparation is unchanged. End-to-end use
of this entrypoint with the protected LLVM corpus is still the next check.
The manifest format is deliberately breaking; no compatibility fallback is added.

[Native checks](checks.json) verify the actual functions used by the product:
the 20,497-byte captured prefix and binary/Unicode values agree exactly, the old
pinned source survives a rename and later publication, and the later tail is
excluded. The captured input remains usable after removing the synthetic source.
Service read registration returns the exact complete cut; publication and owner
acquisition are rejected before a writer lease is created. Changed physical
heads, missing owners, existing targets and nested targets are rejected. A
truncated source leaves neither a published target nor staging. Managed project
creation, owner acquisition and complete read views also pass.

The [kernel audit](proofs.json) checks five laws using standard axioms only,
including exact captured-head membership, bounded copy steps and the actual
Owner field that excludes captured sources. It does not prove the OS, arbitrary
external file mutations or all IO aliases. Initial elaboration/controller
refusals are retained separately and are not successful runs.

The [347-object product](native.json) and [328-object mixed observer](mixed-native.json)
have consistent native inputs. [Source comparison](sources.json) permits exactly
the seven declared product modules and their embedded source bytes. The mixed
observer includes all product core with [unchanged common sources](mixed-sources.json).
The numerical model, ranking, graph facts and lifecycle/delivery oracle are unchanged.

## Two DBs, fourteen mixed clients, interruptions and restarts

The [predeclared rerun](growth-plan.json) uses ordinary registered hooks with the
same parent oracle: two empty logical project DBs, four physical owners each,
four writers concentrated on one owner, and up to ten concurrent readers.
It mixes new/existing/resumed contexts, clear/compact events, interrupted tools,
three actual service restarts, late and duplicate Post/Stop events, captured
write destinations during a project switch, and four waves of growing data.
No manual `keep` or `warm` is used in this workload.

Reader gates include prompt and Stop; preceding SessionStart is outside the
gate. Every actual hook, including starts, is checked independently.
The [independent reconstruction](summary.json) verifies **72/72 semantic queries**
and **1,476/1,476 required original appearances** against actual callback bodies
and visible-context lifecycle: 390 in new bodies, 1,086 in retained visible
context, and 110 in fresh contexts. There are **50 distinct frozen requirements**.
All **504 commands / 429 hooks** succeed with empty stderr and no incomplete
notice. Maximum hook time is **2.327 s**, maximum actual body 26,324 UTF-8 bytes.
This is the existing 500,000-character small fixture, not the public default.

The [original guard](growth.guard.json) finishes normally with no owned PIDs;
sampled related peak is **3,554,368 KiB (~3.39 GiB)**. The 4,358,524 KiB stop and
5,000,000,000-byte user ceiling are unchanged. The [read-only native census](storage-summary.json)
verifies 75 observations, 25 answers and 50 stored fields, unchanged publication
files and final queries matching the frozen inventory. Four observations retain
unknown timing. Raw inspector `originalRunPassed=false` is a legacy constant;
actual whole-run status comes from the original guard and independent summary.

## Cleanup and limits

Ended fixture DBs, session caches, helper builds, temporary files and unused
generated native artifacts are [deleted without archives](retired.json).
Protected native hashes are checked before and after, and the retained product's
[native closure remains consistent](after-cleanup.json). The current candidate,
comparison parent, required model and protected LLVM original remain.

These tests invoke the ordinary hooks directly, not the Codex UI or answering
models. They establish the declared local mixed workload. Large growing DBs,
sustained 80-person operation, NAS/remote deployment, production p99 and general
98% necessary-evidence delivery remain unverified. Accepted LLVM seed and both
topic passes remain **0/6**, matched total-token/quality comparisons **0/18**,
adoption **0**. Next, freeze DB-present LLVM requirements before delivery and test
the real corpus through this connected route under the existing admission rules.
