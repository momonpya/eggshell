The controller preserves every source imported by the product, including
helpers under `tools.research`. New research control is added separately.
Before model dispatch, the existing linker-based audit must verify the native
dependencies, every product module and unchanged common source stamps. Counting
only freshly compiled modules is insufficient and is no longer used.

One executable handles acquisition, memory trials, publication finalization,
original-source audit, read coverage and history. Recorded seed and memory
plans have distinct path projections: a memory trial uses its actual arm DB,
private data root and configuration, rather than a guessed transcript child.
The actual model, provider, effort and completed protocol are checked.

Stage closure requires all declared arms to complete with known inclusive
usage and no owned processes. Actual recorded turn intervals must follow the
declared order. Only after native publication, replay, warm and original-source
checks pass is the candidate's next source/private-history snapshot frozen.
Unknown or failed trials stop advancement and retain their charged records.
This controller supports one recorded attempt per arm; an explicit retry cost
ledger is required before any retry can contribute to an adoption comparison.

Native controller checks use the real earlier RPC stream, plus labelled
metadata mutations for duplicate starts, a missing completion, reversed clocks
and an actual failed-generation record. No model is called by these checks.
The actual rejected source publications must also be replayed through this
fully audited controller. Neither test is counted as a seed or six-stage run.
