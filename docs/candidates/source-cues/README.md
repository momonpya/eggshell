# Preserve lexical source positions through evidence selection

Isolated, unadopted continuation of [source-route](../source-route/README.md).
The ordinary runtime remains unchanged. No answering model or encoder is
called; this is not a token comparison, an LLVM result or the 80-person gate.

## First-drop diagnosis

The [parent replay](parent.json) retains the exact original A0/B1 cut and the
previously fixed two original-observation requirements. Both MCP observations
are nominated, hydrated and readable. Their prepared original geometries exist
and cover their complete 18-character outputs, with native occurrence witnesses.
The [actual parent body](parent-output.json) nevertheless contains neither.
The independently queried complete topology also hydrates every original.
This is not source loss or missing preparation.

Lexical nomination carries owner order but no window positions. An original
tool result is represented by contextual record units; their value comes from
window/citation/synaptic cues. With no such cues its unit covers no valued piece.
A whole historical answer keeps its owner value. The selector therefore chooses
the two notebook answers even though the original data fits. Enabling source
graph expansion alone had already failed; the missing cue contract occurs
after nomination and hydration, not before them.

## Candidate

Use the existing lexical normalization to find every matching position in the
already hydrated original windows, once for each admitted owner. Feed these
positions through the existing evidence refinement. The branch applies only
to lexical recommendation. It changes no owner nomination, rank, weighting,
threshold, delivery limit, Work/Union/completion authority or freshness rule.
No whole-DB scan, extra owner hydration, synapse reconstruction or new cache
is introduced. Question-dependent matching remains query work; it does not
rebuild query-independent metadata.

The Lean theorem `LexicalEvidence.positions_exact` characterizes membership as
an existing in-bounds original window with a lexical match. It also gives
completeness for these matching windows; there is no new position-count cutoff.
[Law checks](../../../tools/research/LexicalCueLaws.lean) cover the tail, empty and
negative matches, duplicate terms, all positive windows and multilingual text.

The same-cut replay excludes private usage on both sides and validates each
retained component under the executing runtime before rebuilding its transport
frame. This is explicit test transport reassembly, not a product fallback or a
second seed. Original DB heads must remain unchanged.

An earlier explicit split-selector diagnostic encountered `Json.setObjVal!` on
a null plan from the non-recommendation pass. Its guard exited normally and the
body was unchanged, but the diagnostic panic is a failure and is retained.
The clean parent replay disables that optional splitting and verifies the
original geometries independently. The receipt-writer issue is not repaired
as part of this selection candidate.
