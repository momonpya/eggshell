# Numerical RPC attribution under independent search actors

This observer is isolated after the numerical-ready candidate. Product core,
model, complete source cut, ranking, selection and deadlines are unchanged.
There are no answering-model calls; paid comparisons remain0/18 and adoption
remains false. The fixture is the previously seen synthetic sixteen-owner
development cut, not held-out work or an80-person workday.

The [patch](candidate.patch) returns bounded request-local timestamps inside
successful numerical replies. Native accept, frame read/parse, encoder/scorer
admission, projection preparation, pipe write/read, completion and output-ready
are observed. Client start/receive are added to existing receipt counters.
The trace-off erasure law is checked by ordinary ContractAudit. Profiles retain
at most128 reply records per numerical metric; observed drops are zero.
Failed current RPCs have no returned trace and remain unmeasured.

The same sealed [native controller](controller.patch) is used for parent,
observer trace-off and observer trace-on. It also saves client rows before
optional statistics and adds a32-client diagnostic. This checkpoint is not a
power-loss durability guarantee. Parent and both16-client observer arms deliver
all32/32 required originals with ACK and semantic handoff. Actual stdout bytes
match for every corresponding case. The32-client observer delivers21/32.
[Actual-body verification](verification.json) covers140 outputs including primes.

For returned32-client RPCs, median roundtrip is711ms: frame read83ms, scorer
admission355ms, projection preparation12ms, score kernel8ms and output-ready to
client152ms. These are nested wall intervals, not additive CPU measurements.
The raw line read median is1ms; observing its completion adds6ms, at most154ms.
These observations motivated the separate numerical-waits experiment, rather
than changing search weights or expanding the clock.

The observer build initially failed on an IO record expression and a missing
parenthesis. A separate setup used Lean's reserved identifier `seal`; its guard
launch found no settings and started no workload. [Preflights](preflights.json)
preserve those failures. The final build, client build and all trial guards are
terminal with no owned processes. Resource bounds are unchanged.

The [profiles](rpc-profiles.json) retain returned traces, [memory](memory.json)
retains sampled engine descendants, and [evidence](evidence.json) retains CPU and
failed cases. Neither sampled RSS nor stack occurrences identify allocation
sites or CPU percentages. Finished private DBs/caches/raw logs are retired after
capture without archives; source restoration and follow-up status are recorded
with [numerical-waits](../numerical-waits/README.md).
