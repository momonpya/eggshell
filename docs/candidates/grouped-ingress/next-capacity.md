# Keep concurrent owners; share preparation at the project scope

The eighty-client mixed trial fails: all writers succeed and all82 originals
survive a fresh-process audit, but preparation takes126 seconds and fresh reader
delivery is58/80. Do not call this eighty-person capacity, run paid answering
comparisons yet, or repeat the same burst before a concrete correction.

Independent original owners are necessary and remain. One physical append
region has one live writer; different regions can publish concurrently. The
number of users does not have to equal the number of append regions. Neither
collapsing the project into one mutable source head nor raising owner/worker
counts to pass this fixture addresses the measured duplicate work and queues.

Grouping eliminates pair-specific replay jobs, not pair-specific relationships
or all destination-wide replay. Sixteen destinations still project the complete
cross-owner relation. Trace preparation attempts and the existing shared-fact
producer on these fixed source identities. Separate original-private usage and
delivery state from the immutable project WorkGraph/synaptic structures; the
latter should be prepared once for the authorized complete project cut. Keep
source-qualified identities and all three edge kinds, read-only scopes and
complete certification. An arbitrary physical owner is not project authority.
First compare the resulting facts/status, original references, e-class and
certification domain against complete current replay, including late feeds,
source replacement and multiple read projects. Commit only changed feed work.

Foreground queueing is a distinct open issue. Sixty-three observed operations
have median20,237 ms in queue and686 ms of work. The first three work periods
take5.8–6.6 seconds and readiness2.3–2.7 seconds; later requests sometimes still
take about5 seconds. Use their retained phase records to locate the responsible
producer before changing it. Existing reader images and page caches already hit
(for example, builds2 with84 hits); do not reimplement that cache or assign all
startup time to MiniLM. Count restoration/validation/ranking work for a fixed
public cut and reuse the immutable result at the service lifetime where valid.
Requester questions, local Union, usage and freshness-dependent decisions must
retain their private/current scope. Limits and certification completeness stay
fixed.

Only after the concrete producers are corrected and independently checked,
repeat the ordinary mixed workload with attempt-level accounting and actual
received bodies. Keep no heavy per-poll replay scan. Record readiness separately
from a fully drained preparation queue, and report semantic fallback separately
from successful lexical delivery. A short synthetic80-client pass would still
leave growing projects, multi-host/NAS, sustained eight-hour use, real98% evidence
and matched token/quality adoption to validate.
