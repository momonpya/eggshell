# Capture independently prepared source inputs through the normal route

Isolated continuation of [source-owners](../source-owners/README.md). Not adopted;
ordinary runtime `52e9dd63…` remains unchanged. No answering-model calls or paid
token comparisons are made. The 80-person, eight-hour, 30-second/98% goal stays
active; this is a small native integration check, not that acceptance test.

Normal source warm now prepares each source-owner root after its lexical index
and before query-input readiness/debt acknowledgement. Identity and bitmap
storage belongs to the configured project cache; a read-only preparation uses
the existing private project overlay. There is no registration of source-head
tuples. Independent original publishers do not acquire the derived dictionary
writer. Its serialized updates still need capacity testing.

At the original turn boundary, the normal project context captures all available
query inputs, including source heads, lexical/windows/numerical/canonical/shared
and private-usage references, plus individual owner inputs. The private pending
record transports a typed frame through a JSON envelope. The worker decodes it,
restores exactly the original cut, checks source/model/encoder/producer and passes
the frozen roots through admission. The queue rejects replacing those roots.
This retains direct references after name retirement instead of consulting a
new latest tuple. Two Lean theorems establish the source/head inventory checks;
they do not prove all IO or physical extent reclamation.

The prepared federated consumer uses original Work-class lookup, one joint
All/Union/child reader family, exact owner/population metadata and nominated
point reads. It reuses the already opened original snapshots instead of opening
another family inside owner metadata. Structured Work is not filtered by a
recommendation K. Conservative allocated-node counts are labelled as traversal
fuel, never as scoring populations. Keyed numerical nominations can merge equal
owners through the shared identity namespace; actual MiniLM is not tested here.

Different project identity dictionaries remain incompatible. The isolated
dispatcher explicitly retains the complete reference federation for that case;
it does not remove a project to enter the prepared path. This is unfinished
cross-project performance work, not an 80-user solution or an adopted fallback.

## Native evidence and failure

The [checker](../../../tools/research/SourceRouteChecks.lean) creates one logical
project with two original owners. It uses actual owner leases, native capsule
publication, normal `Warm.run` and the normal automatic-handoff wrapper. B's
second publication depends on A0, not A1, so A0/B1 is a valid closed cut. All four
old/new root combinations compose and their owner/candidate populations equal
the independent full catalogue.

After 66 later source publications and preparations, both original completion
names are gone. The normal worker still restores the turn's original A0/B0
inputs, including private usage, and service admission rejects root replacement.
The checks also run `ContractAudit`; its syntactic coverage is not an IO proof.

[Native results](native.json) report a 317 ms initial handoff and byte identity
with the complete reference, but **both return notebook answers and omit both
required original MCP observations (0/2)**. This is not successful evidence
delivery. The missing observations exist in the original DB and are connected
by saved All edges. The [source-graph experiment](../source-graph/README.md)
tested the semantic-provider-only graph expansion using the same retained
original cut and question. It still delivered 0/2 originals and was rejected;
enabling that expansion alone is not a repair.

Early diagnostic code called the lower-level compute function without the
normal prepared synaptic context and obtained no body. After using the actual
automatic wrapper, both implementations return the same answer-only body.
Those preliminary failures are retained rather than substituted for the normal
result. One publication fixture initially failed to route its logical request
to its physical owner. Type/record errors and an obsolete-executable control
mistake are also retained in [negative checks](negative-checks.json). The runner
now refuses execution if the latest build failed or its checker source changed.
The first assertion failure left the publication daemon running; the aggregate
guard reaped it. The checker now always requests normal service shutdown.

## Still required

The private turn envelope currently needs every source to be ready at capture.
Cold or continuously advancing sources need a complete prefix/delta preparation
contract; choosing only a ready subset would violate the goal. Names retained
for 64 publications do not replace read-interest/extent lifetime management.

Actual multi-source MiniLM, normal Pre/Post/Stop and source-only recovery,
read-only permissions, bounded shared-cache accounting, cross-project namespace
joins, sustained preparation capacity, large fixtures, NAS/multiple hosts and
the 80-person eight-hour workload remain unverified. Necessary-evidence delivery
and matched total-token/quality comparisons still gate adoption. Models remain
uncalled and comparisons remain 0/18.

The [cleanup record](cleanup.json) removes ended controlled fixtures and the
rejected graph experiment's executable/build/core, without an archive. The
second cleanup accounts for 309,827,811 apparent bytes; an interrupted first
cleanup removed ended fixtures/raw logs before its size observer encountered
an obsolete build symlink, so those earlier bytes are not included. Protected
originals and retained runtimes match their original hashes. Only the active
`source-route-fixture-fixed` case remains for the next same-cut diagnostic;
it is not retained as historical experimental data.
