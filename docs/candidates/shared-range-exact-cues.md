# 検索した原文範囲と配送用の周辺文脈を分ける

隔離した新実装の記録。検索窓の座標の誤りを修正したが、全6段階の必要コード配送にはまだ合格していない。
回答モデル・seedの追加投入は0。本体、READMEの実績、リリースへは採用していない。

`meaningContext?` は窓の中心から配送用の周辺を広げていたため、検索していない文字にも
被覆価値を与え、長いWorkと元観測の境界では実際の交差を捨てる場合があった。
`SourceWindow.project` で、512文字・384文字ずらしの窓と元観測の正確な交差へ統一した。
返る範囲が元観測内・512文字以下で、元の検索座標と一致することを一般の長さについて証明した。
JSONの復号可能なデータ座標へ整列してから局所前提を閉じ、外側の引用符や半端なescapeを必須本文にしない。
前提や周辺を配送することと、その部分に検索の価値を付けることを分けている。

実際の検索窓とWork除去処理を使う1,130件の境界比較、日本語・絵文字、長いWork、JSON原文の試験が成功。
ContractAuditは本番の呼出し先と証明の公理を検査した。ライブラリ、test support、TestMainのelaboration、
実バイナリのビルドも成功した。MiniLM、provider、Worker、鮮度検査等の保護7ファイルは前候補とSHA一致。

別のnative試験では、warm/doctorの48窓、差分追加、破損、モデル変更、DBだけからの再構築を確認した。
期限切れ試験には古い検証前提が三つあったため、実バイナリが同一の検証checkoutで分離して修正した。

- 検証用の語を現行のprimary/auxiliary表現で作る。以前は全224比較が空同士で一致していた。
  修正後は非空132件・空92件が通り、全母集団の重みで順位が逆転する検査も通った。
- 子プロセスへ検証用configを明示し、外側のベンチconfigを引き継がせない。
- 字句索引だけを先に準備する。後段の数値キャッシュcold試験は冷えたままに保つ。

その後、意味検索は完了しても窓位置を返さない小さな記憶が空の応答になる、本物の配送漏れを確認した。
新しい選択器が、すでに入場した完全な本文にも位置指定を必須としていたためである。
期限切れ・cold-to-warm試験全体は未成功。検証の修正でこの実装不具合を合格扱いにしない。
