# 位置指定のない入場済み本文を捨てない

新しい範囲選択器の汎用的な配送漏れを隔離修正した。nativeの期限切れ・cold-to-warm試験は成功したが、
題材1・3の必要コード選択はまだ未達。回答モデル投入・新seed・本体採用は0で、削減率の新しい実績はない。

直前候補では、意味検索が文書を推薦しても窓位置を返さない場合に、すでに入場した小さな本文を捨てていた。
`SharedRangeAdapter.prepare` が、局所文脈と完全な投影の両方に位置指定を要求していたためである。
修正では、上流がすでに入場させた完全な投影を一つの候補として保持する。
本文・出典・native controlのフィールドはそのままコピーし、所有者の順位から一つの需要を与える。
本文の長さで価値を増やさず、数値の窓位置を捏造せず、断片を全文へ広げることもしない。
位置指定がある元観測の局所文脈は、直前候補の正確な検索範囲と前提閉包を使う。

原文の座標・JSON整列・グラフ引用保持・MiniLM・索引・鮮度確認は維持した。
原文や前回回答の全文を新たな必須予約枠にはしない。予算に収まらなければ完全な投影も選ばれない。
保存済みのMatch/Union以外の認定根拠は増やしていない。

## 実コマンドで確認した配送

検証用DBの字句索引を準備し、数値キャッシュを冷えた状態から試した。
古い検証用語の表現とconfig継承の問題は、[検証差分](semantic-deadline-fixture.patch)として分離している。

| 条件 | 実フックの時間 | 確認した結果 |
| --- | ---: | --- |
| 窓位置を返さない意味推薦 | 1,171 ms | 推薦された元の本文を配送 |
| 意味照合を停止させる | 14,499 ms | 期限切れを記録し、字句検索でDB本文を配送。providerも回収 |
| 数値キャッシュが冷たい | 179 ms | DB本文を配送。foregroundで元観測を埋め込まず、warm依頼を1件登録 |
| 別managerが残件を回収した後の新チャット | 1,047 ms | 意味検索が完了し、元DBのキャッシュを再利用 |
| 同じ質問の別チャット | 291 ms | sourceとqueryの実cache hitを記録 |
| 数値キャッシュを破損させる | 167 ms | 使用不能を記録し、字句のDB本文を配送 |

元チャットのディレクトリを削除してから別managerがwarmを回収した。
元DBのheadが変わらず、削除したチャットも復活しないことを検査した。
数値の有効窓はcold時0、回収後4（discovery/focus各2）。字句索引自体が冷たい場合の試験ではない。
postingsと全母集団の順位比較は非空132件・空92件で成功した。
出力本文・SHA・バイト数・実配送ACKを毎回照合し、未完了通知だけを成功には数えていない。

## 同じ修正候補で全6段階を再確認

題材1の最初から順に、各段階で独立した2チャットを使った。

| 1 | 1周目・題材1 | 1 | 14.844 / 8.939秒 |
| 2 | 1周目・題材2 | 0 | 11.517 / 9.818秒 |
| 3 | 1周目・題材3 | 2 | 12.529 / 11.129秒 |
| 4 | 2周目・題材1 | 1 | 17.074 / 15.125秒 |
| 5 | 2周目・題材2 | 0 | 16.108 / 14.139秒 |
| 6 | 2周目・題材3 | 5 | 18.388 / 16.168秒 |

全12本文が段階内でバイト一致し、30秒以内に完了した。数値検索は完了し、元観測cacheの
欠落・使用不能・フック内再埋め込みは0。ライブラリ・ContractAudit・アダプタ試験・test support・
TestMainのelaboration・実バイナリのビルドが成功した。
一連の検査の最大RSSは3,052,704 KiBで、3GiB監視と4GiB上限を維持した。
構文、テストのOption取得、テスト用の区切り文字の費用計算の失敗も消さずに保存した。

必要コードの欠落は直前候補と同じである。今回直した、小さな記憶の完全な脱落とは別の問題として扱う。
窓を持つ元コードの候補・前提閉包・共有できる原文の費用を調べてから選択器を変更する。
撤回済みの所有者ごとの価値正規化や、過去回答の全文予約を繰り返さない。
全6段階の必要コードが揃うまで回答モデルは呼ばない。

[修正差分](shared-range-atomic-projections.patch)は[正確な検索座標の候補](shared-range-exact-cues.md)の後へ適用する。
検証用には別のfixture差分も必要。[全記録](shared-range-atomic-projections-review.json)に実本文SHA、
受領記録、失敗、資源監視、保護ソースのSHAを保存した。
差分の適用には `git apply --unidiff-zero` を使う。
