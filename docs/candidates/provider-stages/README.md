# The numerical startup lock blocks independently active chats

This isolated observer narrows the previously measured typed-provider interval.
It does not change the model, ranking, certification scope, source cut, clocks,
budgets or worker topology. It uses the existing request-local callback and
writes timestamps once in the existing final receipt. Missing span ends remain
unmeasured; wall intervals are not CPU time and nested spans are not additive.

Both sixteen-client/two-wave controls deliver32/32 actual original bodies+ACK
and32/32 semantic handoffs. All32 output byte digests agree with tracing on/off.
At eighty concurrent clients, tracing ON delivers0/80, OFF1/80. These are failed
capacity gates, not an improvement. All236 actual outputs are independently
checked and retained with their byte hashes. No answering-model calls are made,
and paid matched comparisons remain0/18.

In the traced eighty-client wave, all80 finish encoder opening, exact scope
pinning, prepared-input restoration and matrix binding. Input restoration is
median1,046/max1,464ms. Encoder opening is median4/max15ms; the numerical
directory is median2/max192ms. Repeated configuration hashing is not the
dominant observed interval in this run.

All80 enter query encoding and none finish it. Twenty-one acquire the numerical
startup lock, with completed wait intervals median3,007/max9,811ms. Those21
enter endpoint checking and then authenticated ping without a measured ping
end. The other59 have no completed lock-acquisition span. Backend arithmetic
cannot be blamed for work these requests have not reached. This locates a
shared connection/startup bottleneck; it does not by itself prove that removing
it will make the complete WorkGraph handoff fast enough.
