# 原文・引用束の点別採点：不採用

同じ受理seed・保持製品720e64d9・題材1/2/3の捕捉済み実選択入力を使用した。元の120,000文字/480,000byte制限を変えず、57原観測の質問位置付き短片と過去回答19段落をQwen3-Reranker-0.6B Q8で採点し、原単位の束を順位順に入れ、既存の証明済み貪欲充填を行った。正解リストと実配送本文は判断入力の準備に使っていない。

| 題材 | 現行の実配送 | 候補の選択原文に存在 | 判断対象の全束の和集合に存在 |
| --- | --- | --- | --- |
| 1 | 2/5 | 2/5 | 3/5 |
| 2 | 6/7 | 5/7 | 5/7 |
| 3 | 5/6 | 3/6 | 3/6 |
| 合計 | 13/18 | 10/18 | 11/18 |

選択原文の推定器は、現行の実本文18ラベルをすべて再現することを先に要求した。候補の列は実フックの配送測定ではない。候補は悪化しており本体接続・回答モデル実験・採用は行わない。元の全候補には18項目があるが、判断器に見せる短片/束の段階で7項目が失われている。点数、上位件数や窓幅の調整を繰り返さない。

成功した数値採点は題材順13.276/13.235/14.337秒、計114,872入力token。初回は長い非座標出力を渡してcontext超過で失敗した。失敗ログで完了を確認できる入力は少なくとも3,415tokenで、取り消された実行中の消費は不明。失敗を無料と扱わない。数値試験の最大標本RSSは1,341,008KiB。すべてのguard終了とownedPids空を確認した。

判断を自律的な履歴検索・原文確認に切り替えるという利用者の指示に進む。読み取った原文を根拠ID/範囲として返し、元のWork依存と配送に接続する。モデルが読んだだけで配送成功とは数えない。

終了した候補のsource/build/runと旧点別採点モデルは削除し、圧縮archiveを作らなかった。保持製品、受理seed/履歴、次の検証入力と推論engineは維持した。最終判断は[decision.json](decision.json)、独立監査は[model-domain.json](model-domain.json)、[削除結果](cleanup.json)を参照。
