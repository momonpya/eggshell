# Rejected: graph expansion alone does not deliver original observations

Unadopted model-free experiment following the
[normal-route integration](../source-route/README.md). The original-evidence
denominator remains `original A0_MARKER` and `original B1_MARKER`; neither was
delivered by the parent, although both are stored and have All paths from the
recommended historical answers.

The shared indexed discovery implementation expanded the source neighborhood
and hydrated its related outcomes only when `semanticMatcher.isSome`. Lexical
recommendation could find an answer without expanding those relationships.
The candidate replaces those two provider-presence conditions
with the existing `recommendation` predicate. Numerical focus still requires
its numerical command; nomination, ranking, thresholds, weights, budgets,
certification, prompts and source freshness are unchanged.

The parent and candidate replay the same authorized original heads, targets,
question and lexical model-free harness. This is not a second independently
generated seed. Their shared retained components must satisfy each executing
runtime's normal lexical/window/canonical/synapse/numerical validators before a
current transport frame can be assembled. Private usage is excluded on both
sides to isolate graph expansion; the separate integration test retains actual
private usage across 66 publications. Runtime transport provenance is not
bypassed, and original DB heads must stay unchanged.

The [parent](parent.json) delivered 0/2 originals in 318 ms; the
[candidate](candidate.json) delivered 0/2 in 323 ms. Both completed normally.
The [actual candidate body](candidate-output.json) adds the B0 notebook answer
but still contains neither required original MCP observation. This experiment
does not establish a practical speed difference or a delivery improvement.
The two-condition change is rejected. Its isolated executable, build and DB
copies are deleted after extracting these records; no archive is made.

The original observations are ordinary text atoms in the stored graph, not
structured values rejected by a text-only candidate filter. Native tool
occurrences intentionally contain observed output before invoked Work. Neither
structured-output exclusion nor reversed occurrence fields explains this case.
Trace the first drop between support-owner hydration, admissibility and final
selection on the retained parent cut before changing ranking or weights.

Results are not a substitute for actual MiniLM, LLVM 1/2/3 and second-round
evidence/token/quality comparisons, or 80-user capacity/deadline testing. The
full goal and the token adoption gate remain unchanged.
