# Retain completed roots while preparing skipped source publications

Isolated continuation of [captured-preparation](../captured-preparation/README.md),
not adopted. Multiple independent original append owners within each logical
project remain mandatory. Original publication, Work equality, recommendation
authority and budgets are unchanged.

The [patch](candidate.patch), relative to `cut-preparation-core`, connects the
retained-basis writer to lexical, window-owner, shared synapse, canonical and
source-owner preparation. Numerical assignment uses the same basis path;
its actual encoder/matrix execution is not tested in this stage.

Completed roots live in a per-component/source B-tree catalogue. Exact names
repeat the full source head, component identity and checksum. The exact name
and logical latest pointer change together; an older source cannot replace
logical latest. Readers continue using their captured immutable roots.

Background preparation follows actual source publication parents to find a
completed ancestor, bounded to 4,096 publications/8 MiB. It applies that source
difference while appending beyond the current physical published extent. A
checked complete physical header can repair a missing catalogue entry. Original
sources and the project-shared vector matrix are not rewound or copied.
The catalogue still needs retention/compaction leases. A missing ancestor can
require explicit bootstrap; this is not a proof of bounded whole-source warm.

The [Lean checker](../../../tools/research/PreparedCutChecks.lean) uses ordinary
native publication/warm/turn capture/worker validation/Handoff. After preparing
A0/B0 it captures unprepared A1/B1, then prepares A2/B2 first. It verifies both
required responses in the complete eight-owner original domain **before**
observing readiness. A1/B1 initially have no completed inputs.

Explicit historical warm now succeeds in 111/110 ms. Lexical and window-owner
preparation report `publication-delta`; canonical reports `owner-delta`.
The worker retains A1/B1 and delivers both required original responses in
343 ms. A2/B2 remain available, future originals do not enter the old cut,
and original heads are unchanged. [Result](native.json), [actual body](body.txt).
A [fresh process](restored.txt) restores the same references and identical body.
These small two-owner results are not a controlled speedup or 80-user capacity.

The full build includes ordinary ContractAudit. [Lean laws](laws.txt) show that
the actual ancestor/promotion lineage preserves identity, authority and revision
direction, using only `propext` and `Quot.sound`. They do not prove native IO,
scheduling or complete delivery. [Failures](negative-checks.json) retain three
corrected compile errors. [Resources](resources.json) record aggregate peak
2,829,584 KiB including builds, no resource trips and no owned survivors under
the unchanged 3.5 GiB stop/4 GiB ceiling/2 GiB disk floor. This is not an
eighty-client memory measurement. [Identity](result.json) records helper
`968bf3b4…` and unchanged original publication/project/scheduler source hashes.
MiniLM/answering-model calls are zero; matched token comparisons remain 0/18.
Existing product, README results and releases are unchanged.
