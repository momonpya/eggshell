# Captured query inputs before worker admission

Isolated continuation of [retained-source](../retained-source/README.md), not
adopted. Multiple independent append owners within the selected logical project
remain mandatory. This candidate keeps the existing ownership, write routing,
shared project/scope vectors and read-only reference projects. It addresses
query input lifetime, not sustained writer capacity.

Normal warm publishes a bounded record containing the completed window-owner,
lexical, partition, matrix, shared-synapse and canonical recipe roots for the
original source it actually consumed. A lexical repeat preserves an already
completed numerical pair. The record contains no question, body, ranking or
private usage head. Private usage is captured separately for the requester.

Before execution admission, the manager captures one small immutable record per
configured source, together with the full original head inventory. A queue entry
does not hold a separate original payload or complete set of opened readers.
The worker restores those exact roots; it does not choose latest or require the
old source name to remain in the bounded completion directory. Raw DB readers
also restore the captured original head, rather than reopening latest after a
queue wait. The keyed provider and legacy federated scoring/focus receive the
same fixed matrix roots. Routing and scoring keep their existing exact matrix
equality witness. Captured lexical reads keep the normal original membership
checks and logical read observations.

Actually empty sources stay in the complete original/certification inventory;
they need no fabricated lexical or numerical root. A populated source without
prepared inputs is unavailable, never a completed empty search. Ordinary warm
readiness includes the combined input record. Publication precedes its ready
checkpoint and debt acknowledgement. No ranking weights, selection budgets,
MiniLM model, certification domain or original bytes are changed.

The manifest is a set of independently validated completed roots, not a new
atomic transaction spanning all components. Descriptors protect a waiting query
from source-name directory eviction. Physical page reclamation/compaction still
needs a retained-extent protocol and is not established here. Canonical payload
borrowing still starts during active query processing and uses the existing
charged cache and bounded lease.

The new reference source-identity theorem uses only standard Lean axioms. The
ContractAudit checks the captured lexical route, original observation path,
exact historical restoration and absence of warm/publish calls in admission.
These pure/structural checks do not prove all concurrent IO or heap behavior.

The first ordinary read-only-project test rejected a prepared original. Its
diagnostic showed the exact matching record in user read-cache while admission
returned none: an early return at the missing database-side manifest skipped
the user-cache branch. The final candidate makes absence local to that branch.
This was a defect in this new candidate, not evidence that the original DB lost
its observations. Compile failures and the failed native case remain negative
evidence; their results are not final-helper successes.

The final [native root check](roots.json) takes 4,222 ms and carries 4,266 bytes
of metadata for its populated source. Sixty-six later prepared publications
evict both old lookup names, while serialized lexical/window/vector/shared and
canonical roots retain the same contents. A [fresh process](reopen.json)
restores them too. Foreign producer/matrix, missing inventories, latest-source
substitution, actually empty versus unprepared populated sources, and lexical
repeats preserving numerical roots are checked. Vectors here are explicitly
synthetic and two-dimensional. The guarded process peaks at 109,632 KiB RSS;
this is not a MiniLM or capacity result.

The final [normal native lifecycle](context.json) retains six source views and
passes prompt/Pre/Post/Stop in 338/106/85/25 ms. Its read-only reference project
uses user read-cache, native ingress/imports and source ACKs preserve the captured
boundary, and queries do not advance original heads. The actual [MiniLM mixed
burst](workload.json) delivers both small fixture evidence items in all 80
queries and durably ACKs all 80 saves across four append owners. Median/p95/max
delivery is 15,174/15,960/16,054 ms, with 27 semantic replies and 53 lexical
fallbacks. One populated original cache entry is loaded once and hit 79 times;
all 80 acquired original handles finish released, with zero active/readers or
charged lease bytes. Empty sources still belong to the original inventory and
do not acquire fabricated original payloads.

[Normal preparation](drain.json) drains in 4,119 ms with nine retries, preserving
all 80 original response atoms and 327 numerical windows with zero missing or
invalid rows. A new semantic query takes 2,045 ms and, after verified service
restart, 2,475 ms with the same body hash. The full guarded scenario is 31,576 ms,
not one hook's latency; sampled aggregate peak RSS is 2,715,856 KiB. The existing
3.5 GiB stop/4 GiB hard limit and disk floor are unchanged. Cancellation, queued
expiry and foreign-save rejection deliberately produce negative-control log
messages. All guards finish with no surviving owned process.

The conservative `PreparationRegistry.complete` probe remains false for three
of four sources, as also observed in parent records. `drained` checks consumed
tickets, prepared roots and the current replay checkpoint after an attempt;
it does not replace external-dependency validation or claim those observations
remain permanently fresh. The independent original/window census is retained
separately from both readiness flags.

Exact [helper identity](result.json), [resources](resources.json), failed checks
and the earlier read-cache diagnosis are retained. The normal workload uses
unchanged MiniLM; it is distinct from the synthetic root test. These short,
small-fixture results do not establish a controlled speedup, sustained capacity,
98% necessary-evidence delivery, quality or token improvement. Answering-model
calls and matched paid comparisons remain zero; the candidate is not adopted.

After sealing compact records and the actual prompt output, [cleanup](cleanup.json)
deletes four ended fixture DB/cache trees, 414 closed/generated files and the
superseded helper: 179,402,581 apparent bytes. No equivalent physical-space
reclamation is claimed. Protected originals and fixed inputs remain unchanged;
no archive is created. Current source, object/interface/link inputs and the
final helper remain available.

The existing full federated catalogue still restores Work structure. Complete
cross-owner certification and transitive read dependencies, many-source
admission, multi-host authentication/NAS durability, source-only recovery of
prepared descriptors, 80 people for eight hours, p99 below 30 seconds at the
declared sustained input rate, 98% necessary evidence and matched total-token
improvement remain unfinished. Small burst results cannot establish those gates.
