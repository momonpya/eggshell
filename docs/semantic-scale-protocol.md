# Expanded warm-DB latency gate

Freeze this protocol before measured hooks. This is a practicality diagnostic
of the isolated combined retrieval candidate, with zero generation-model calls.
It is not a latest-public-main adoption comparison or a token/quality result.
The [original 48-hook protocol](semantic-latency-protocol.md) and its archived
results remain unchanged.

## Saved fixtures

Use original-window counts **2, 1,024, 10,000, 50,000**, not owner counts.
Compile `tools/RetrievalScale.lean` against the original save-time retrieval
policy. Save one graph per size, once. The two-window fixture has two owners.
Every larger fixture has one owner with 32 distinct original windows and
one-window owners for the remainder: respectively 993, 9,969 and 49,969 owners.
Assert both unique window keys and references equal the requested count.
The graph producer saves at most 32 owners per transaction and can resume only
after checking the complete saved prefix against its predetermined source text.
It performs no model inference and does not add new sources inside a trial.

Keep the saved PageMap publication, exact graph-file hashes, owner/ordinal
catalogue, source construction, model/runtime and helper contracts. For each
candidate arm, copy that same original graph and explicitly warm both lexical
and numerical derived data. Save the pre-warm graph hashes and complete warm
result; reject a changed source graph or incomplete preparation. Repeated warm
must add/hydrate/encode zero. Numerical receipts count original window
references, distinct cached keys and segment vectors separately.

An actual previously used DB is an additional 12-hook stratum. Copy and seal
its original graph first; preserve every owner and window. Freeze its three
questions and expected original-body evidence before any measured hook.
Record its original use and provenance. A legacy experiment's data can be
used for latency diagnosis, but its old LLVM/token results do not become a
contribution of the new paper.

## Native cells

For every synthetic size use DB-owned and user-private derived layouts, fresh
and cached questions, and exactly three predetermined repetitions: **48 hooks**
per executable. Each repetition uses this question for all synthetic sizes and
layouts, where `n` is 1, 2 or 3:

> Find kernel realtime clock observations for monotonic scheduling and elapsed timers, question n.

Use a read-only profile and OS write protection for both layouts during measured
delivery. Private warming also runs while the DB is protected. Put each pair
in a fresh data root. A new native chat supplies the fresh question; shut down
all provider processes, then another new chat supplies the same cached question.
Ask the native helper to validate its actual question-cache keys and contract;
do not hardcode the old cache filename. If an initial failure did not populate
that cache, prime it separately, recording the complete setup cost and result.
Retain the failed measured attempt.

The compiled semantic cap remains 4,500 ms, limited to half the remaining native
deadline. Preserve the five-second complete-semantic/original-body gate and
actual hook deadline. Never widen the cap, choose only faster repetitions,
remove failed cells or replace them with standalone phase timings. A failed
sample, incomplete publication or missing ACK fails its cell. Report every
individual observation and count out of three for each cell. No aggregate
average can hide a bad size/layout/cache condition.

Record stdin, stdout, hash, bytes, flush time, ACK, semantic status and route,
query/source cache probes, initialization and embedding, original references
scored, segment counts, cache open/read/decode/check, ranking, matching,
lexical fallback and cleanup. Preserve preparation costs separately. Neither
an observed provider prefix nor a surviving cache subset certifies full scoring.
Do not clear OS page caches; this is not a cold-disk experiment.

## Bias and threshold diagnostics

Record query and source segment counts beside the native measurements. The
read-only `retrieval_bias_audit.py` additionally compares the actual original
128-token numerical path and the complete candidate on fixed unrelated
multilingual texts. Source windows have 96, 256 or 512 characters. Source- and
query-segment-count strata and language/length strata are all reported, with
all individual scores. The scorer is the candidate's pinned NumPy kernel.
Comparing the full source bundle with its first segment holds the actual
vectors fixed and checks the maximum's expansion effect.

The question list is split before scoring: first four topics per language are
calibration, last four are held out. Compute the 99th-percentile candidate
score using calibration only and report its held-out pass count alongside the
unchanged 0.38 threshold. This controlled null dataset has no positive/recall
labels and does **not** authorize adopting a threshold. A changed cutoff or
length normalization still needs independently labeled positives, actual task
quality, equal matched token trials and deadline completion. Language strata
alone cannot isolate a causal effect of segment count.

The pilot must retain each correct source's full rank, source length, distinct
primary/auxiliary term counts, window/segment counts and whether it was delivered.
This diagnoses accidental long-document matches before considering BM25-like
normalization or a continuity bonus. Do not add an unmeasured scoring constant.

The similarity-equality arm must report actual generated unions, completed
deliveries and omitted Work separately from identity nominations. Existing
scripted native evidence already distinguishes ordinary/control union counts;
it does not establish effect on real tasks. Keep the sixth intervention's
Exact, child-membership and freshness boundary explicit. A further Exact-free
intervention, if needed, belongs only to predeclared perturbed-task controls
and never to the production soundness theorem or ordinary Phase 3 denominator.

Build, preparation and inference stay serial under the sampled aggregate
3,500,000 KiB descendant-RSS guard. Retain failures and partial saved prefixes.
Only measured bottlenecks determine whether packed matrices, hook-scoped
encoder sharing or residency should come next. The full original scoring
domain and complete-rank checks remain mandatory for any storage optimization.

## Separate first and continuation strata (2026-10-20)

The user now permits 10–30 seconds for an initial hook. Keep the original
fixed five-second collections above unchanged. `initial_scale_probe.py` declares
a separate 48-hook collection against the same saved synthetic publications:
four sizes × two layouts × three fixed questions × first/subsequent prompt.
The initial cap is 30 seconds overall; the subsequent target is five seconds.
Semantic search receives at most 15,000/4,500 ms respectively, limited to half
the remaining native deadline so lexical body delivery retains a reserve.
Measure in the fixed order 10,000, 50,000, 2, 1,024 windows. Report every case,
including completed lexical fallback separately from completed semantic search.

Prepare discovery and focus to completion once for each common publication,
then copy it into every cell. Preserve the original graph and every existing
vector byte. Record the added focus-window difference and its preparation cost;
repeat warm must add/hydrate/encode zero. Each destination must also complete
warm and doctor before measurement, with zero additional source encoding.
Use the same three questions recorded in the original scale manifest. Each
pair stays in one live session, with acknowledged evidence retained in history.
An empty subsequent result is not another body delivery. This does not measure
latency for a new follow-up question or demonstrate generative answer quality.

Both cache layouts use a read-only profile and OS-protected source DBs during
hooks. Private warm also protects the DB. Managers remain owned by the runner
for descendant RSS accounting; record both manager/client shutdown exits.
Retain raw stdin/stdout, per-invocation receipts and the original five-second
classification alongside the separately declared policy/body outcomes. No
partial ranking or notice-only output counts as semantic/body completion.
The 12 owned-manager LLVM observations are a separate already measured stratum;
these 48 synthetic hooks do not replace them or establish token adoption.

An intermediate diagnostic may stop at a complete measured-pair boundary to
prioritize a required implementation fix. Keep the completed raw observations,
record the interruption and list every remaining case as unmeasured; do not
report a completed 48-case gate or balanced adoption comparison. The remaining
cases stay required. Never resubmit an already measured hook to replace it.

For subsequent candidates, `--ready-inputs` may copy the completed discovery/focus
inputs from an earlier stratum. Verify its frozen source tree and authoritative
graph hashes, retain its manifest and preparation hashes, require the same
encoder contract and zero new embeddings, and preserve every original vector
byte. Lexical metadata may be rebuilt for changed code. This is reuse of the
same saved snapshot, not a separately generated seed.
