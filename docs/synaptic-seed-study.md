# シナプス実装後に新規取得するseedの比較

2026-10-23。旧seedを復元した計測は、新しいシナプスの評価から外す。
旧seedには新しいPre/Post/Stopを通した導出来歴がなく、既存の原文を配送できたことだけでは消費辺を評価できない。
旧試行の本文・usage・失敗・費用は保存し、旧seedの段階2以降を再開しない。

## 固定する条件

- seed取得と候補の全6段階は同じruntimeを使用する。対象はcanonical-record-ackの`d1370cc5c718ed43e92152013dd1eba65ba4cbd01b150e5dcb3652571fb4cdd2`。
- 元のseed質問をそのまま使い、LLVMの同じcommit、gpt-5.6-luna/xhigh、AGENTS無効、モデルfallbackなしを固定する。
- native CLI・実行計画・Leanハーネス・hook bundle・設定と実行体のSHAも、モデル投入前に凍結する。
- remote plugin同期はCLIで無効にし、固定した候補フックだけを実行する。実threadのinstructionSourcesは空であることを確認する。
- seedは独立した空DBと新規チャットから3本取得する。取得費用は利用時の費用と分け、失敗消費も保持する。
- 実装・抽出・監査・制御はLean。既存MiniLMの数値ライブラリ境界だけを例外として保持する。サブエージェントは使わない。
- 重い処理を直列にし、合計RSSを監視する。通常3GiBで停止し、利用者の4GiB上限に余裕を取る。

## 実行順とゲート

1. **モデルなしの合成試行。** 空DBに対して実runtimeのSessionStart/UserPromptSubmit、Pre→実ツール→Post、Stop、keep、終了を通す。
   時系列と原文の証拠を持つ消費辺、引用支持と共引用、私有の利用記録を実際の出版と索引から確認する。
   読み取り対象・行・識別子が元の出力にある場合と、ない場合を含める。試験から辺を直接挿入しない。
2. **seed取得。** 同じ固定runtimeで3回、独立した空DBと新規チャットから元の質問を実行する。
   実Pre/Post/Stop、全コマンド、保存出版、導出来歴、最終回答、usage、終了管理の証拠を保持する。
3. **全コマンドの監査。** コマンドごとにPre/Postと出版された元観測を対応付ける。
   消費辺の有無を、対応あり・先行コマンドなし・入力との一致なし・未対応形式・証拠不足等の理由とともに列挙する。
   すべてのコマンドが過去出力を消費するわけではない。全件を分母にし、結び付いたものだけを数えない。
4. **配送を見る前の正解凍結。** 各seedの保存済み原文だけを読み、題材1〜3に必要な範囲の保存有無・指紋・元所有者・原文座標を確認する。
   DBにない範囲も欠けとして記録する。質問と必要範囲、監査結果のSHAを固定した後に初めて配送を実行する。
5. **同じseedで比較側を確認。** 現行の比較runtimeを別に固定し、その実行体が同じseedの独立コピーをopen・warm・配送できることを確認する。
   保存元のSHAを前後で照合する。別々に取得したseed間の差を現行対候補の効果としない。
6. **同時期のfreshと6段階。** 古いfreshは新しい比較に再利用しない。
   各seedをブロックとして、現行・候補・freshを同数実行し、題材1・2・3と2周目を測る。順序はseed間で循環させて事前固定する。
   seedごと・題材ごと・周ごとの結果を残し、入力+出力、cached input、失敗費用、品質、全フックの30秒期限を確認する。

同一seedの継続チャットでは、DBとユーザー私有の利用記録を保持する。段階ごとに私有領域を空へ戻して利用辺を消さない。
`prepare-live`は直前の固定checkpointとの一致と既存の設定・daemon終了を検査し、同じ私有領域でwarmと2チャットの確認を行う。
`prepare`のsource-only復元はDB持ち運びの検証用として区別する。
比較時は各段階の元checkpointを両側で同一にし、私有の利用記録を含む入力も固定・記録する。

全体の集計だけで悪化を隠さない。3seedを独立した比較ブロックとして扱い、1seedの結果を一般化しない。
追加反復が必要なら結果を見る前に数と比較順を固定する。最終採用はAGENTS.mdの条件による。

## 保存量

3本のseedはhead/pages/writerと必要な永続来歴を保持する。checkpointへderivedや私有cacheを複製しない。
各条件の作業DBは直列に再利用し、完了済み段階のDBとcacheを無制限に積み上げない。
失敗時も生RPC・usage・本文・元出版の照合に必要な証拠は保持する。
