# 同じ原文の表示条件をaliasで分断させない候補

2026-10-30。隔離したモデルなし検査。前の群加点案は題材2で退行し不採用なので、加点の単位・係数・対象を調整し直さない。

今回変えるのは、既に検証済みのbounded recordの原文行を、別のownerの小さい候補から選んだ場合にも一緒に購入すること。段落/字下げの観測済み境界だけを使う。新しい言語parserやcall→definitionの推測、巨大関数の必須化、正解位置による窓の追加を行わない。行の同一性と表示上の同席は別の関係であり、Work/e-class/Union/認定は変えない。

表示partitionは出版側で構築し、source/view/scopeで固定する。照会ではpostingを引く。連結は既存recordだけから作り、読み取りgap、異なる内容指紋、未保存bytesを補わない。検査済みrecordの完全性と元行保持、閉包のidempotenceをLeanで証明する。これは表示条件の証明であり、そのrecordが質問に必要という証明ではない。最小partitionの定理や差分更新の実装まで済んだとは扱わない。

最初は捕捉済みの基準の題材1で、同じcost/weight/fixed/limitを使う。元のproposal番号を保持し、原文の物理closureを表示partitionで閉じる。同じ閉じた物理closureを指すaliasは、その既存cueの和集合を共有する。cue自体の値を変えない。原文行以外の原子は保持する。元proposalは必ずその元payloadを保つ。必要な原文が増えても元のwire上限を超えない。

選択後だけ凍結正解を開き、3/7/4の分母と部分保存3097行を保持する。題材1で改善しなければ実runtimeへ進まず、この規則の係数・幅・対象を変えて再試行しない。前の群候補の題材2入力への適用は、分断の対照診断であり、その群候補を採用し直す根拠にしない。実フック・両周・総token・品質・80人条件は別途必要で、本候補は未採用である。

## 結果：表示単位は守れたが、必要根拠は増えず不採用

同じ基準の題材1の入力で、全8,276原文行、2,078個の検証済みrecordを使った。2,340提案の原文closureを拡張し、閉じた物理closureは5,588クラスになった。既存の値・費用原子・上限・proposal番号は不変。選択・再束縛は789 ms、物理費用119,997文字/119,999 bytesだった。

選択済みrecordの分断は0になったが、凍結した必要根拠は**2/3→2/3**で、部分保存のtracked-input-languageは未配送のままだった。表示の分断をなくすことと質問の必要根拠を選べることは同じではない。事前の停止規則どおり、実runtime・題材2/3・回答モデルへ進めず、この強制閉包案は不採用とする。係数・境界・正解位置を入れて再試行しない。[実結果](candidates/canonical-record-domain/replay.json)。

元行保持、追加されたaliasからもrecordが分断されないこと、閉包のidempotenceを任意入力で証明した。改変されたラベルとサイズの拒否、読み取りgap・異なる指紋の分離、物理aliasの既存cue共有、完全なrecordでも予算超過なら選ばれないことを合成入力で検査した。これは必要性の証明ではない。実リンク85 objectは整合、再生guardは終了0・残存0・関連RSS標本最大154,752 KiB、元source不変、実フック0・回答モデル0。本体・README・releaseは変更しない。
