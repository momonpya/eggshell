# Reuse original lexical evidence within one pinned request

This isolated Lean candidate removes repeated validation of the same lexical
owner and an unused Work-spelling index open. It extends the
[separated discovery candidate](separated-discovery.md); it does not replace the
product runtime, README results or release. Recommendation, generated e-class
recognition, three synaptic edge types, original freshness and extraction remain
separate and connected. No deadline, embedding model, score or selection policy
changes in this candidate.

## A smaller original access path

The 50k reference performs nine posting queries naming 399,753 rows and requests
1,199,259 owner/member/candidate point keys. Most rows name the same owners.
Instead of adding another persistent index, one pinned source/index pair now
shares a request-local map of validated original bytes. A witness retains the
index owner ordinal, original live member ordinal and original candidate value,
with proofs of all three decoded facts. Unknown owners still use the original
bounded authenticated B-tree reader and original counter IO decoder.

A hit replays every logical point observation in its original order. It also
checks the incoming posting ordinal; sharing an owner cannot hide a conflicting
posting. Ranking obtains the already certified member ordinal and records the
same original member dependency. A new query always allocates a new map; a later
publication cannot borrow an earlier reader's witness. Physical reads are shared,
not authority or source identity.

The controller no longer opens the large prepared Work-spelling index, because
the preceding structural change removed its consumer. Its uncalled surfaces
callback remains lazy. Complete original class and child recognition remain
independent of recommendation K. No Bloom filter, routing service or second
database is required to remove these particular reads.

## Verification boundary

`LexicalReadsAudit` uses the unchanged scalar posting reader as its oracle.
For the original 10k and 50k publications, all 24 terms agree in ordered owner
IDs, counts, error behavior and full ordered source/index read traces, including
charged bytes and completeness. Traces reset between terms, so deduplication
inside a trace cannot conceal missing cache-hit observations. Every ordinal for
9,969 and 49,969 matched owners also agrees with the original member getter and
its reset trace.

Ten fixture states include absent/malformed/trailing values and conflicting
member/index ordinals. Further checks cover a previously validated owner with a
contradictory posting ordinal, repeated terms after trace reset, an unvalidated
ordinal, a retired owner in a new publication and continued validity of the old
pinned query. A 1,024-key multiple-leaf case preserves present/absent values and
ordered dependencies, rejects escaped/unbounded requests and authenticates a
corrupt root even for an out-of-fence key.

Ordinary Lean witness invariants, refreshed ContractAudit dependencies,
MatcherFixtures and the preceding nominated-evidence contract pass. The new
call-graph audit requires actual original checks and observation replay, and
rejects unused Work-posting opening by indexed discovery. These are byte-witness
invariants and executable IO comparisons, not a complete filesystem refinement
proof.

An initial fixture failed: the candidate rejected an inconsistent member before
recording the candidate point, whereas the original monadic reader obtains that
point before its Boolean rejection. Both unknown-owner and cached-owner paths
were corrected. The failure, diagnostic and rerun remain recorded. Earlier
attempts to equate opaque primitive IO actions were abandoned; no axiom was added
and the original IO decoder remains in use.

## Native measurements

The final runtime runs one actual first/ACK-history pair per original read-only
source, using the existing MiniLM boundary, new private question/chat state,
source-only prepared cache copies, native stdout/publication SHA checks and
owned-manager shutdown. These are diagnostics, not a p99 cohort.

| Source | First | ACK-history continuation |
| --- | --- | --- |
| 10k windows | 9,812 ms; original body 17,803 bytes | 7,944 ms; semantic search complete, duplicate body suppressed |
| 50k windows | 22,897 ms; semantic timeout, lexical original body 21,346 bytes | 22,584 ms; incomplete notice 356 bytes, memory offer rejected |

All four bodies match their corresponding stored separated-discovery bodies,
including the failed 50k continuation. This is not a newly paired speedup trial.
The earlier recorded times are 10,485/8,783 ms and 28,206/28,355 ms respectively.
The candidate preserves original delivery order while removing physical reads.

For 50k, the same 399,753 rows now request 149,907 point keys, one three-point
validation for each of 49,969 owners. There are 349,784 validated hits and 49,969
certified ranking-ordinal hits. Posting time is 3,107/3,091 ms, including
912/906 ms of point-batch preparation; those are overlapping timings. The stored
reference records about 6.7 s inside postings and about 4.4 s preparation.
The first/continued lexical lanes take 8,080/7,878 ms. The numerical lane still
times out at approximately 14.3 s under the unchanged half-window policy.

The continued notice has a concrete controller cause: the current receipt says
`disposition=empty`. `SearchDelivery.empty` requires a current accepted stamp and
a successfully decoded empty worker result. The controller then turns **every**
empty lexical result into `pendingSearch`, even with time left. This is distinct
from a missing, malformed or expired reply. The next change should retain the
semantic timeout in its trace while distinguishing valid empty lexical delivery
from failure; increasing the timeout alone cannot fix that conversion. The
diagnosis is recorded, not fixed by this reader candidate.

10k explicit warm/repeat take 21,541/20,882 ms; 50k take 146,437/147,315 ms.
All four produce no source embeddings or projection rows and write zero matrix
bytes. These full explicit-verification costs remain outside the hook table.
Maximum aggregate RSS across the executions is 2,180,944 KiB, under the 3.5 GiB
guard and 4 GiB ceiling. All guards and owned children finish. Root and original
lexical-index file hashes remain unchanged. Rebuildable old test executables and
terminal helpers were hashed and deleted without archives; current/reference
runtimes, sources, raw receipts, link inputs and the current compiler cache remain.

The [review](candidates/lexical-witness-review.json) pins the patch, source,
compiler/link inputs, raw receipts, failures, retirements and consistency check.

## Scope

Source embeddings, answering-model calls and new seeds remain zero in this
check. Explicit warm is outside foreground timing and records projection work
separately. Matching a stored body is not a new matched token or quality trial.
AGENTS.md still requires topics 1/2/3, both laps, equal predeclared replications,
inclusive total tokens, quality and deadlines before adoption.

Large posting lists and full numerical scoring remain proportional to corpus
size; a bounded point batch does not bound total query work. The request-local
witness map also grows with distinct matching owners. Normal federation still
constructs its global catalogue. This does not establish million-window capacity,
p99, private MCP capture or concurrent shared-DB readiness. The broader design
continues with one scoped original reference model, one source-change feed and
separate recommendation/authority views, rather than a collection of copied DB
subsystems. Phases 0–6 remain active and unfinished.
