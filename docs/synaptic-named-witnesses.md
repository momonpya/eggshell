# 位置と語の種類を検査するLeanの導出抽出

隔離候補である。位置欠落と分類の不具合を修正したが、配送の欠落解消・総トークン改善・最終採用は未達である。
順位式・MiniLM/WindowCentroid・配送プロンプト・認定規則は変更していない。

## 名前と区切りを分ける

同じ出力の最初の語しか残さない不具合を修正すると、旧分類の別の誤りも顕在化した。
数字を識別子、`//`や`/`をパスと扱うため、[位置保持だけの中間候補](synaptic-positions.md)では
850件中505件が数字からの辺になり、1フックが未完了通知になった。中間候補は不採用として保持する。

`termKind?`で、既存のUnicode文字/数値/結合文字表を使って名前の候補を検査する。
単独の数字を独立した名前の証拠とせず、識別子候補は名前から始め、パスには名前のある成分を要する。
`--flag`や`12p`を識別子とせず、`/123`や`src/日本語.cpp:10`はパスとして保持する。
題材名・正解範囲・手作業の除外語リスト・順位係数は入力にしない。
日本語・韓国語・キリル文字・アクセント文字と分解形も回帰試験に含める。

これは限定した字句の候補規則であり、すべてのツール引数やPOSIXパスを解析するという主張ではない。
文字列が一致したことを意味的な消費や真の因果関係の証明にも使わない。

## 証拠とキャッシュ

`Pending`は、辺の語の種類の検査結果、実引数と実出力の範囲に同じ語が現れること、
有効性と厳密な時刻順序を持つ。検査済みの`pending.edge`だけをグラフへ渡す。
同じ名前の後続出現は保持し、引数の重複や通知の再送では証拠を増やさない。

- `numeric_not_a_witness`: 数字だけの語は分類を通らない。
- `unnamed_path_not_a_witness`: 名前成分のないパス区切りは分類を通らない。
- `Pending.non_numeric`: 抽出経路が受け入れた辺の語は数字だけではない。
- 両文字列の原文一致、出力の範囲内性、完了が開始より前であることの4証明も維持する。

新しい公理・`sorry`・`native_decide`は追加していない。実観測の真実性やツールの意味論までは証明しない。
共有索引の実装印にUnicode表の実バイトも加え、分類コードや表が変われば古い索引を準備済みと扱わない。
手動の版番号は追加せず、元観測・来歴・数値モデルは保持する。
Match・Union・completed・現在の操作省略をこの関係から生成しない。
