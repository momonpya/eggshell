# 実入力の選択量と、期限を外した診断

未採用。回答モデル呼出し0。C7の同じ固定snapshotを使ったモデルなし診断であり、新しいseedや実フックの合格ではない。

題材2の実workerを120秒の診断期限で実行した。初回33,345ms、同じ準備済みDBから受領記録を付けた再実行32,608ms。どちらも本文117,761文字、SHA-256 `79dd88bfdf40208f0903b639afe6e5ec701ec96afd72b98cc6103d04e9956045`で一致した。独立した元原文の監査は両方3/6件。実フックの30秒条件を外したため、この3件を期限内配送成功とは数えない。直近の実フックの結果は別候補の0/15件のまま。

実際の選択入力は18,974候補、15,209費用node、27,452cue、node参照99,298件、cue参照129,910件。最大重み263bit、全重みの最大公約数1。共通因子の除去では小さくならない。723候補の選択と最後の停止まで724回の全走査、約1,374万候補の再評価になっていた。数値精度、候補数、重みや順位を変える前に、変わらない部分木の勝者を再利用する隔離候補を検証する。

欠けたcache key、入力言語の状態、HLSLの分岐は、すべて入場・復元・候補範囲の段階を通っていた。cache keyとHLSLの元所有者2件は、それぞれ推薦1/3位・focus5/2位で候補1,220/1,114単位、選択0単位。入力言語の所有者は推薦4位・focus3位で444単位中212単位が選ばれたが、必要範囲は落ちた。候補全体の和集合は必要原文をすべて覆っており、この診断の欠落を座標抽出や未入場の問題とは説明できない。

raw recordとcanonical file rowでは共有費用の単位が異なり、前者には重なる範囲や所有者のframeの費用がある。ただし、それが欠落の原因だと断定する監査はまだない。重みの再調整や過去に失敗した予約枠へ戻らず、描画した本文と費用モデルの対応を次に確認する。
