# シナプス結合は一般のツール観測を扱う

2026-10-24。ソースの行範囲は、ツール観測全体の代わりにならない。
対象にはMCP、DB結果、検索結果、構造化JSON、通常のテキストを含める。
基本の出典は元のWork・Outcome・Occurrenceと、原文内の範囲である。
ファイル・指紋・行番号は、別に確認できた場合の追加情報とする。

## 確認した欠陥と候補修正

Journalの再生は、元のツール呼び出しに `command` または `cmd` が
あることを要求し、通常のMCP引数をunknownとして飛ばしていた。
出力の射影もJSON配列や、単一のテキスト出力を選べないオブジェクトを拒否していた。
元のツール出力の保存と、この後段の欠落は区別する。

候補では一般の呼び出しを `invocationInput` で扱う。
ネストした引数の値を照合対象とし、オブジェクトのキーとツール名は引数の値に混ぜない。
ツール名を含む元の呼び出し全体を開始・終了で別に照合するので、
同じ引数を持つ別のツールで置き換えることはできない。
単一の文字列出力へ射影できないJSONは、その完全な原文と座標を保持する。
`workCommand` はソース読み取り専用の追加デコーダであり、一般の記憶の入場条件にしない。

Leanの `SynapseInvocationTests` で、実DBに保存した2件のMCP観測について、
ネストした引数、JSON配列・オブジェクト、元のツールの同一性、
ファイルに依存しない消費辺1件、両観測の来歴を検査した。
既存の `SynapseJournalTests` も通過した。
外部のMCPサーバーや回答モデルは呼んでいない。

これは隔離候補の検査であり、製品runtime `efb9a11d…` と
比較用runtime `6818f093…` は変更していない。トークン削減率の採用ゲートは未実施。

## 段階実行前に閉じる残り

- 推薦・配送・利用記録にも、元の観測内の範囲を直接参照する単位を通す。
  現在の `Offer.source : Range` などは、依然としてファイルを要求している。
  一般の消費辺が記録できたことを、一般の出力が配送されたこととは数えない。
- ソースの座標はコマンド名の列挙で決めない。指紋を確認した原文と
  保存出力の一致で検証し、座標不明の観測も保存・推薦・配送から落とさない。
- 消費辺は、元の観測・範囲の同一性で重複をまとめた後に、証拠の種類と
  異なる接続先の数を使って伝播強度を定義する。raw witness件数を重みにしない。
  規則とその減衰・冪等性の性質をモデル実行前に固定する。
- 位置だけ渡す場合も、証拠付きの原文範囲を独立させる。
  連続しているだけの数百行を一つの必要範囲に結合しない。

完成した候補runtimeを固定してから、その同じruntimeで空DBからseedを取得する。
修正前のseedと後段runtimeを混在させて実装効果を主張しない。
