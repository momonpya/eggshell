# 一問だけの利用フィードバック診断

2026-10-28、回答を一度も開始する前に固定する。[Astra相談](astra-progress-review.md)に従い、既存C7の題材2を一回だけ実利用し、その後の同一source publicationとeventsから、今回のusage追加分だけを変える対照を行う。新seed・fresh・重み調整は追加しない。

製品runtimeは`3551bb5ad8df6ce3387e237e80f5c27f6f5149762edb0c70b75de893ce82687c`、モデルはgpt-5.6-luna/xhigh、AGENTS無効、質問・LLVM commit・必要範囲は既存の凍結定義を使う。原C7は読取り、モデルは新しい私有作業用コピーへ書く。途中の保存・索引の完了と配送本文を記録し、既知欠落はpilotとして記録したまま入場する。

回答モデルへの入場は最大一回。失敗時も再試行しない。回答待ちの期限はturn/start直前から900,000 ms、使用量通知の入力＋出力が1,000,000以上になった最初の通知で中断要求を送る。cached inputとreasoningは内数であり加算しない。通知はproviderが累積値を送った時点でしか観測できないため、この値は課金の厳密な上限ではない。超過分・中断・未知の最終費用も隠さず記録する。モデル代替を許さない。全関連processを3.5 GiBで止め、4 GiB未満を維持し、空き2 GiB未満では開始しない。

同じ質問に対する初回の配送を記録し、保存済みで未配送だった範囲の実再消費を確認する。完了後の一つのsource snapshotを両側へ渡し、原文・過去回答・events・以前からのusageを一致させる。片側は今回のusageを含み、他方はその追加分だけを除く。比較は回答モデルを追加せず実hookで行い、原文・出典・期限を監査する。

利用辺が発生しなければ効果未観測で停止する。辺とrootがあっても本文が改善しなければ、この仮説で6段階へ拡大しない。必要原文が増え、既配送項目を落とさず、期限と資源条件を満たして初めて、同じsnapshotを使う事前同数複数反復の総token比較へ進む。この診断を初回95%配送、token改善、品質維持、80人運用の合格に数えない。
