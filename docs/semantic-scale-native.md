## Collection and evidence checks

`semantic_scale.py` freezes executable/helper hashes, encoder inputs, questions,
source hashes and the protocol before collection. It explicitly warms lexical
and numerical indexes, requires zero work on repeated warm and a warm doctor,
then freezes the complete derived tree. Both layouts use OS write protection
and a read-only profile. A native helper checks fresh/cached query conditions
against the actual compiled cache contract; provider processes end between
new chats. Maintenance, cache-cost inspection and any needed priming are
recorded separately from the fixed 60 hooks.

A passing observation requires the complete original discovery domain,
all references scored, all source cache hits, no foreground source encoding,
full tokenizer-mapped character coverage, completed semantic status, original
body in actual `additionalContext`, byte-exact stdout/publication/hash, on-time
flush, accepted offer and completed ACK, and elapsed time below 5,000 ms.
Distinct cached keys can be fewer than window references, while every original
reference must still be scored. A provider prefix never certifies completion.

`check_semantic_scale.py` passes 22 counterfactual checks. Replaying five existing
native records accepts the four complete DB/private fresh/cached cases and
rejects the changed-assets pending case. These are recorded cases, not five
new hooks. An interrupted observer recovers retained stdout and receipts rather
than submitting a measured prompt again; missing evidence fails the attempt.

## First retained observations

The collection is still running in
`semantic-scale-20261020/combined-1`; its complete result has not been certified.
The 2- and 1,024-window strata each passed all 12 fixed observations. At 1,024
windows, fresh questions took 3,206–3,495 ms and cached questions 1,609–1,780 ms.

The first six 10,000-window observations all failed the gate at about 28.8
seconds. The first fresh receipt records 4,508 ms of semantic timeout followed
by 24,224 ms on the lexical route. Actual stdout contained the incomplete
notice, not original DB body; offer acceptance was absent. This fails the body
delivery requirement as well as the five-second gate. Keep the failure; do not
replace it with a faster resample or a standalone timing.

The separate complete 10,000-window cache-cost inspection reports, across its
three predetermined passes: open 1.042–1.050 seconds, read 0.032 seconds,
decode 0.329–0.345 seconds and validation 0.082–0.084 seconds. Each pass reads
66,116,736 bytes from 10,000 existing cache objects. These measured costs justify
examining storage, but cannot explain away the 24-second lexical route. The
next inspection must separate posting reads, owner validation, ranking and
the rest of delivery before choosing the optimization. Full rankings and
original scoring domains must survive any change.
