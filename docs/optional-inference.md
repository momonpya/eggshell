# 推測した依存を原文の必須条件にしない

2026-10-28。隔離候補。比較基準は`70678fb544061bdb86ae91b3015d9695e65e675c901a445eccb5f89bfa478a62`、固定した元snapshotと題材1の質問を使う。回答モデルの計測は停止したまま。

現候補は関数名の字面から推測したcall→definitionを、元原文の必須payloadへ追加する。意味的な必須依存ではないと実装自身が明記しているため、引用や消費から得た根拠と分ける。

一つの変更だけを試す。原文行とcost atomの対応の検査を保持し、推測した定義を各offerの強制依存へ追加しない。関数範囲の任意offer、シナプスの引用・消費・共起の束、原文recordの完全性、認定、モデル、重み、配送枠、位置や出典の表示は維持する。コード以外のMCP・ログ等にも原文の取得条件としてC++の推測を要求しない。

以前のdirect-evidence候補はこの変更と表示変更を合わせ、29秒で本文を生成できなかった。今回はその複合候補を再実行せず、原文bindingとrecordの準備を出版側へ移した現在の16.6秒の基準から、推測の強制だけを分離する。前の失敗が成功したとは扱わない。

比較は同じ元snapshot・MiniLM・質問・候補生成・固定済み47引用診断を使う。全47を必須項目の分母に変更しない。基準と候補の実本文、完全配送と欠落の差、別ファイルの原文、遅延、原文不変、終了を記録する。独立に凍結した原文集合や分母が変わった試行を改善としない。

基準の準備済みviewは候補へコピーして再利用し、同じ実装のviewがあるときに全warmを繰り返さない。改善しなければ1試行で止め、重み・範囲・予算を調整せず撤回する。改善してもAGENTSの同条件の複数反復・inclusive total token・品質・両周・全題材の採用条件を代用しない。98%と80人運用は別途未達である。
