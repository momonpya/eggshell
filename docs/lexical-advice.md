# Lexical nomination and consumed original validation

Isolated candidate after `0174ef8`, not adopted. No source embeddings, answering
model or seed ran. Product sources, README claims and release are unchanged.

The scoped router's lexical nominations no longer validate every matching
original owner. They read the existing source-bound lexical index, its complete
postings, frequencies and original ordinals. Only the bounded lexical owners
actually consumed for the scoring domain pass the original indexed/live ordinal
and candidate checks, followed by original header/reverse-candidate/window checks.
The numerical receiver still validates its selected source owners separately.
This moves validation; it does not give a lexical hint equality, Work, freshness
or completed authority. The existing complete e-class path remains independent.

There is no new persisted index, cache format, tokenization, source encoder,
vector projection, router partition, score or retrieval threshold. Cold or changed
indexes remain unavailable. A later index publication does not change the reader
held by an earlier nomination result. A bad unconsumed hint can affect advisory
ordering; a consumed hint whose original scalar checks disagree is rejected.
This intentionally differs from eagerly rejecting every unconsumed bad owner.

Query-term weights are computed once. Ordinary Lean proves that all Float
additions, their order, primary/auxiliary lanes, stable ordering and output of
`rankPrepared` are exactly the original `rankRows`. This is not an IO refinement
proof of all stored postings. Original source validity still belongs to the
checked source readers, not the derived index.

The fixture compares complete rankings for nine queries, including multilingual
ones and empty results. Nomination observes only the original `roots` and
`candidates` counters: two source operations. Consuming two owners gives 28 total
source operations. Forged ordinals, duplicate/unnominated consumed owners, and a
selected corrupted index owner are rejected. The old pinned index still works;
changed and cold nonempty sources are unavailable. ContractAudit follows the
actual scoped producer through these nomination and original-check functions.

Ten questions and three repetitions were fixed before timing, with reference /
candidate ordering alternating AB, BA, AB. The 50k source and source embeddings
are identical to the parent. Complete ranked and anchor owner sequences agree
in all 30 cases. The first fixed clock question takes 3,270/2,473/2,442 ms in the
reference and 1,469/1,522/1,495 ms in the candidate. The `timer` query takes
1,167/1,094/1,077 ms versus 205/210/204 ms. Both match 49,969 owners. Zero-result
questions are also retained. These are lexical-only timings, with OS caches not
flushed; they do not measure answer quality, recall or total-token improvement.

The actual native first/continued pair completes semantic search in
11,098/7,891 ms. Both bodies match the parent's saved native bodies exactly;
initial original observation body is 9,316 bytes, continued output is valid
empty/no-new-memory, and stdout/publication/ACK/teardown are recorded. This is
one pair, not p99 or a replicated native speed comparison. Source/matrix/index
preparation is reused after checking the exact source head and current Warm
contracts; foreground code does not build or repair any index.

Numerical reading is still scalar: 3,164 source-window hits cost 4,868 / 3,745 ms
in these first/continued calls, compared with about 11 ms in the actual dot
primitive. That confirms block reading after the router is the next priority.
Full lexical posting enumeration and sorting remain; the cold fallback and
native federation still use their prior paths. Million scale, incremental route
maintenance, required-history recall, all-topic/both-lap matched inclusive tokens
and quality, MCP privacy and the paper remain unfinished.
