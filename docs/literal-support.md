# Literal evidence inside original records

Isolated product candidate. No production adoption, LLVM 95% delivery claim or
total-token improvement claim.

The original-record route was still requiring a quoted identifier to equal a
whole saved line or JSON member. A numbered source row contains its identifier;
a remote URI contains a cited location. Whole-record equality misses both even
when their exact bytes are stored and All-reachable from the answer. Recognizing
more command strings cannot fix that representation mismatch.

## Product change

[LiteralSearch](candidates/literal-support/tools/LiteralSearch.lean) compiles the
past answer's actual backtick quotations into a shared prefix/failure/exit
automaton. It scans the original record's checked literal/decoded spellings for
all quotations together. Every returned witness has a bounded source interval
and proves equality to an actual requested pattern. No case folding, guessed
file coordinate, tool-name rule or model is used. This observes a literal
mention; it does not establish the truth or causality of a claim.

The background builder restricts candidates to that answer's actual
All-reachable original reads. It hydrates each reachable owner once, checks the
original spelling and attaches support/coquotation. Duplicate representations
do not multiply a read/quotation pair. The production collector retains one
witness per requested quotation per original spelling, rather than allocating
every occurrence in a repetitive log. The full-occurrence collector remains a
diagnostic reference. Independent checks cover 2,047 binary strings, suffixes,
overlaps, Unicode and long-field tails; 100,000 repeated characters retain two
witnesses for two present requested patterns. Soundness is proved; a complete
algorithm refinement proof remains outstanding.

Original publication now retains only the validated compact record descriptors.
It no longer constructs and discards an unrelated full-record hash index. The
complete base partition and checked projections are unchanged. File aliases
remain optional, and all of these edges remain advisory. The existing e-graph
certification boundary and handoff prompt are unchanged.

The [integration patch](candidates/literal-support/integration.patch) applies to
the [observed-records candidate](observed-records.md), with the LiteralSearch
module above installed under `tools/`. It is quarantined from the main product.

## Same snapshot diagnosis

Both products warmed exactly the same source-only checkpoint, with separate
private roots. Publication pages and head were unchanged. The original source
contains numbered code and a structured MCP-shaped URI. The answer quotes
`NEEDED_SYMBOL` and `customer/logs`.

| Advisory support in the original record | Parent | Candidate |
| --- | ---: | ---: |
| Identifier inside the code output | 0 | 4 |
| Location inside the remote URI | 0 | 1 |

These are edge counts, not four independent required items. Recorded reads and
all consumption facts were identical. Total original-support edges were 1→6;
total support was 5→10 and coquotation 6→16. Parent warm took 2,485 ms and
candidate warm 1,959 ms on this tiny fixture. They are not scale benchmarks.

The parent already supported a separate `printf` output containing the same
symbol. That does not establish support for the code row containing it. An
initial research assertion incorrectly required zero original supports of any
kind; it was corrected to check the actual containing source ranges. The
completed warm outputs were reinspected without rerunning either warm. The
failed assertion and its guard record are retained. See the full
[same-snapshot result](candidates/literal-support/records/same-snapshot.json).

## Native verification and limits

The parent actual-hook fixture rejects missing code-row support. The candidate
actual Pre/Post/Stop fixture passes both embedded-quote checks, retains 6 native
origins and 13 journal events, and reconstructs support/coquotation after copying
only the DB to a different private root. Read-only new-chat recall delivers the
two frozen small-fixture items in 2,142 ms. The MCP-shaped calls do not contact a
real MCP server.

The final product also passes the 7-observation atomicity/opaque-input/large-JSON
fixture, corrupt-block rejection and independent DB-only reconstruction.
FullSearchOracle was recompiled against it before ContractAudit. Both the
original-record and literal-support dependency audits pass, with only standard
Lean proof axioms and no added `sorry` or `native_decide`.

Final runtime SHA-256 is
`cfbbf02315b322d04fa7759af8305f817af70e7c58018c1c776f70b3248ef873`.
The [review](candidates/literal-support-review.json) records actual commands,
guards, earlier failed research builds/assertions and successful checks. All
guard-owned processes ended. Aggregate product-build RSS peaked at 2,739,312
KiB, below the 4 GiB ceiling. A concurrent publication produced an `original
basis changed during incremental assignment` preparation warning; quiescent
recovery succeeded, and the warning is not declared fixed.

There were no answering-model calls. Topic 1/2/3 and lap-two answering stages
remain 0/6. This addresses format-dependent loss and literal correspondence;
the 500 ms/256-request graph-walk limits, final selection, 95% required-original
delivery, matched repeated inclusive-token improvement, MCP private defaults
and 10–80-user/NAS scale remain separate unpassed gates. The next required
diagnosis uses the frozen real-study requirements; this small fixture cannot
replace that denominator. A changed-runtime answering study still starts with
a new empty-DB/new-chat seed.

Completed trial DB/cache/prefix/helper artifacts were deleted: 27 targets,

an archive. Three obsolete candidate executables were also removed; the current
candidate executable, required object/interface dependencies and actual study
seed remain. Logical bytes are not an estimate of physical APFS space reclaimed.
