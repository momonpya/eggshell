# Compose prepared source owners without whole-tuple readiness

Design following the [independent-cut counterexample](candidates/owner-route/README.md).
The replacement representation has an [isolated Lean component](candidates/source-owners/README.md),
but is **not integrated or adopted**. The target
remains 80 people, eight hours, complete recognition and 98% actual necessary
original delivery within 30-second hooks. Token/quality adoption gates remain.

The [owner component](candidates/prepared-owners/README.md) maintains identity,
ordered originals and exact statistics correctly for a declared tuple. That
does not make every valid cut available during independent publication. The
continuation prepared (A0,B0), (A1,B0), (A1,B1), but rejected valid (A0,B1) although
both inputs were individually ready and the complete engine delivered both
originals. The continuation is rejected. Longer waits, larger name retention,
latest substitution or serializing original writers are not repairs.

Preparation must be factored by original source. A composite cache accelerates
a defined join; it cannot be a new prerequisite for availability. Keep the exact
captured read set and evidence denominator.

## Separate identity from membership

- Maintain stable append-only structural owner ids independently of source-head
  combinations. A digest nominates a bucket; complete streamed bytes and ordered
  authority-tagged references establish identity. Preserve all immutable original
  locations. Identity deduplication never creates a Work Union or completion.
  Namespace/access boundaries must permit the authorized cross-project equality.
- Each source publishes its own exact-head roots: all live Outcome ids, candidate
  ids, original locators, ordinals and canonical-owner lexical postings. Keep
  nontextual Work in the complete domain. Update from checked publication
  differences. Retraction removes membership, not an identity another live or
  retained source still uses.
- Capture every source/head/prepared-root reference with the original turn/read
  boundary and transport them through queued operations. Individually valid old
  and new roots may compose when the existing dependency-closed read contract
  permits that cut. Validate a shared identity namespace and immutable dictionary
  extents. A newer append-only dictionary cannot add future owners to old masks.
  Name eviction must not lose captured refs; compaction still needs extent leases.

Use persistent sparse block bitmaps over checked ids for exact Outcome,
candidate and term-posting unions. OR counts duplicate owners once; removing one
source copy preserves another. Maintain exact union cardinalities for scoring,
never sum overlapping source counts. First-live-source/root order is separate
from identity allocation or bit position.

Share unchanged blocks, cache joins by immutable inputs and keep per-block
counts. An uncached source-root combination must still have a defined correct
join. Measure cold, unchanged and single-publication composition; do not hide a
whole-bitmap/corpus scan inside an incremental join. Source identity allocation
may be independently owned/sharded; original appends must not wait on one
project-wide source queue. This is a design, not measured performance or a
lock-free IO claim.

## Preserve the Work graph

Retain complete all-source Work-class lookup, structured congruence, Exact
positions, original child membership and generated local-Union witnesses.
Recommendation masks/K are not certification filters. Allocated node counts
may bound traversal fuel, not scoring populations.

The [joint topology reader](candidates/owner-route/FederatedDemand.lean) has native
checks against a complete reference for cross-source All paths, duplicates,
Union aliases, structured fallback and child membership. Reuse its shared queue;
independent source closures are incomplete. This is not a proof of all IO.

Vector routing stays advisory and project/scope canonical vectors stay shared.
Restore nominated owners and selected bytes by point/range reads, without
rebuilding all Work/semantic nodes or window directories. Private questions/
usage never enter shared manifests. Read projects receive no writer capability.
Original owners publish in parallel within the selected logical project.

## Exit checks

1. Every individually prepared old/new combination in the counterexample must
   compose without whole-tuple readiness. Add duplicate/retraction/reinsertion,
   new sources, missing/divergent deltas, old pins and name eviction.
2. Full owner/original membership, exact populations, both lexical contracts,
   frequencies and tie order must equal the independent full engine.
3. Class/All/Union/child results stay complete across source/project boundaries.
   Missing individual preparation remains unavailable; actually empty sources
   remain valid. Neither condition can counterfeit a successful empty domain.
4. Verify normal prompt/Pre/Post/Stop, actual multi-source MiniLM, source-only
   recovery and private/read-only scopes before any paid experiment.
5. At growing sizes run combined 10/40/80-client query/publication/preparation,
   then eight-hour load: deadline p99, queue age, stable debt, memory/disk and
   98% actual necessary-original delivery per declared condition. Multi-host/
   NAS and physical reclamation remain separate requirements.
