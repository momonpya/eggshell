# Prepare the shared owner domain outside retrieval

Design for the next isolated implementation, not implemented or adopted.
The target remains 80 people, eight hours, complete recognition and at least
98% actual necessary-original delivery within 30-second hooks. The existing
token/quality adoption gate is unchanged.

## Evidence and rejected shortcut

[The fixed-source federation experiment](candidates/federation-order/README.md)
compares 256/1,024/4,096 native Outcomes across 16 sources, including identical
owners with Exact dependencies. Removing repeated list-prefix copying preserves
the full metadata but gives no consistent practical speedup. At 4,096 rows,
reference medians are 1,644 ms; structural identity, document enumeration and
topology/Union loading account for 1,480 ms in that middle observation.
The proposal is rejected rather than promoted into the current runtime.

After oracle materialization warmed its page caches, the existing all-source
Work-owner lookup takes 17 ms for a two-source Union chain reaching a third
source, 27 ms for all 16 copies of an equal owner, and 3 ms for a negative query.
Generator loading/closure preparation is outside those timers. Results equal
the independently materialized full graph; removing the bridge source denies
the recognition. These are warm lookup/correctness observations, not cold
certification latency, freshness or completed delivery.
Do not rebuild this mechanism or restrict it to recommendation top-K.

## The smallest missing materialized view

Retain PageMap, original source readers, vector/window routing and synaptic
indices. Prepare **owner equivalence, original locations and global statistics**
for the complete configured read set. A query does not need a new canonical id
for every semantic descendant before it can use those facilities.

- Bind the view to every permitted source head, source order, project/scope and
  actual compiler bytes. Its manifest contains neither a question nor private
  usage. Private usage remains requester-specific.
- Give owners a view-specific id; retain all original `(source, node, ordinal)`
  witnesses and a representative. Verify equality with complete ordered
  references and streamed original bytes, including Exact positions. A hash is
  only a bucket hint. Do not copy original bodies into the view.
- Maintain exact live distinct Outcome/candidate counts, owner postings and
  lexical frequencies using reference counts. A duplicate's removal cannot
  delete another live original. Existing owner-term and root-reach directories
  supply changed-owner inputs; do not rescan every document to rediscover them.
- Preserve the first original's order across source permutations, duplicates,
  retirement and reinsertion. A changed internal id must not change tie order,
  provenance or memo meaning. Use a stable id namespace and a checked order
  embedding, or an order-statistic directory; prove the chosen interpretation.
- Semantic population used solely as a termination bound may use a separately
  proved conservative bound. It must not silently replace exact scoring
  populations/frequencies or become an authority claim.

Publish roots only after their entire declared input cut is covered. Update
from the authenticated publication difference; bootstrap/full recovery occurs
outside hooks. A divergent source, missing delta, retired scope or failed
validation remains unready rather than claiming empty data. Keep old pinned
roots during update; a new scope requires explicit preparation.

During retrieval, router/postings nominate scoped owners, the prepared view
resolves their ids/order/originals by point/range lookup, and the existing
all-source class reader handles recognition independently. Restore Work and
result bytes only for actual inference, grounding or delivery. Preserve the
existing Matcher/Extract rules and their generated local-Union witnesses.

All/topology lookup must close jointly across sources: `A→B` in one source and
`B→C` in another must reach `C`. Independent one-hop/local closures are
insufficient. Keep global child-membership checks, structured congruence and
run-local Union changes complete; no relevance cutoff may supply a negative
recognition result. Use the independent full engine to test this boundary.

## Incremental maintenance and exit evidence

[DBSP](https://arxiv.org/abs/2203.16684) provides a formal approach to incremental
view maintenance, including grouping, distinctness and recursion. Here the
design inference is to maintain this small derived owner view from additions
and retractions, rather than add SQL storage or a second general query engine.
[egg](https://arxiv.org/abs/2004.03082) motivates batched restoration of congruence
invariants; the existing verified class reader remains Eggshell's authority path.
Neither paper establishes our performance or evidence-delivery target.

Original appends retain independent owners in the selected project. Prepare
payloads concurrently and keep only short derived-root publication serialized
where required; do not wait for a whole-corpus merge before durable ingress ACK.
Readers of other projects acquire no writer capability. Measure input rate,
queue age, update bytes, retries and preparation debt under concurrent saves.

Require native full-source equivalence over duplicates/removals/branches,
cross-owner topology and unions, old pins, scope changes and source-only
recovery. One added observation must not enumerate unrelated owners/Works.
Then audit the fixed LLVM originals/questions without a model and run the
10/40/80-client combined workload at growing sizes. No scope, original-evidence
denominator or certification domain is narrowed. Keep the old implementation
as a test oracle, not a product fallback. Only after these checks may a fixed
new runtime/seed/cohort enter the required matched token/quality experiments.
