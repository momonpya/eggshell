## 問題の切り分け

残る原文はDB、シナプスの提案、有効な束縛、選択候補まで届いている。したがって現在の残り一件は保存や引用構文ではなく、選択の問題である。ただし、同じ既存スコアを上手に並べ替えれば必要性が分かる、という意味ではない。直接のsemantic focusも弱く、必要性を識別する情報を追加で消費する仮説が必要である。[現在の実記録](citation-origin-repair.md)。

同じseedのnative開始40件をread-onlyで確認した。欠落した関数名を検索引数にした呼出しはなく、最終回答の明示引用もない。過去の識別子検索や明示引用があることを、新しい推薦信号として仮定しない。元観測は`exec-a4acdf31-ca0d-4f9f-84f2-880493760cfa`、保存との一致は[既存監査](candidates/seed-storage-integrity/integrity.json)の`ingress`にある。

一方、配送には同じ関数を呼ぶコードが含まれている。Astraの提案は、この**選択済み原文と未選択原文の間にある、同じ語を介した局所文脈の違い**を使う。関数定義の認識、特定symbol、今回の正解位置、追加LLMは使わない。既往のsource-definition-cuesや、過去引用をbaseから移す試行を再実施しない。

## 相談で出た方式（実装候補として未確定）

現行の選択結果を`S0`として固定する。原文record `r`の字句集合を`A(r)`とし、表示用metadataは含めない。同じ許可scope・resource・内容の版に属する、重複を除いたrecordだけを比較する。

```
d(t) = 語tを含むrecordの数
C(t) = S0のうち語tを含むrecordの字句集合の和集合
a(t) = S0内の語tの位置に対する、現在質問の既存focus係数の最大値

B(r) = max [ a(t) / d(t) * |A(r) \ C(t)| / |A(r)| ]
       t ∈ A(r) ∩ A(S0)
```

共通する語がない、またはその語について配送済みの文脈しかない場合は0。過去引用の親順位を`a(t)`へ混ぜない。頻出語は次数で薄まり、複数の一般語を足して勝たせない。一語の別の文脈が質問に必要だという意味論の証明にはしない。

1. 現行選択を一度実行し、`S0`を固定する。
2. 未選択recordを`B(r) / 正確な未払い配送費用`で比較し、一位を一つだけ決める。
3. その追加を可能にする、現行価値の損失が最小の削除可能recipeを一つだけ探す。依存する共有費用・原文区間・束を一緒に扱う。
4. 単一の置換が成立するときだけmaterializeして実予算を検査し、終了する。成立しなければ変更しない。次点や複数交換を試さない。

追加recordからさらに広げない。別版・別resourceへの同語bridgeも作らない。対応を裏付ける来歴のないMCP等では、その跨ぎを使わない。これは推薦用の索引照会であり、同語を理由にe-classを併合したり、Match・Union・completedへ昇格させたりしない。

## 想定した最小検証と停止条件

最初は同じ原文・実選択traceの隔離Lean診断だけとする。新DB、新seed、全warm、再埋め込み、回答モデルは不要。原文recordと既存の選択単位/recipeの対応を先に確認し、候補の作り直しや今回の関数全体を指定した束を追加しない。`record`の粒度と、追加・削除recipeの具体化はまだ未検証である。

順位と一つの置換を確定してから、凍結ラベルを監査へだけ渡す。必要範囲全体が戻り、既存4件を全て保つ場合だけ実フックへ接続する。欠落が一位にならない、一つの置換では足りない、既配送を落とす、時間/RSS違反のいずれかで停止する。同じ題材を見て語の除外、次数の指数、文脈幅、交換回数を調整しない。

成立した場合も、新sessionの題材1の実本文5/5、30秒未満、集計RSS 4 GiB未満を確認する。Leanで検査するのは、原文来歴、重複不変、既配送文脈の0点、次数による上限、起点の固定、元bytes・費用・認定境界である。自然言語の必要性や95%を証明したとは扱わない。

## 保存・速度・新規性の限界

出版差分ではrecordのsorted token IDs、scope/resource/内容の版/tokenからrecordへのpostings、record頻度を準備する。語の全組合せ・新しい本文複製は保存しない。不変索引はDBサービスで共有し、照会の集合だけを私有の短命状態にする。

時間は訪問postingsと文脈字句数に依存する。最悪では反復走査が増え得るため、上界`a(t)/d(t)`で安全に枝刈りし、deadlineでは変更なしで終える。これだけで数秒、80人、長年の規模を達成したとは主張しない。

[MMR](https://www.cs.cmu.edu/~jgc/publication/MMR_DiversityBased_Reranking_SIGIR_1998.pdf)は質問関連度と既選択との非類似度を組み合わせる。この案は、既選択との正の同語bridgeを条件に、その語について未見の文脈を測る。局所関連、質問拡張、novelty、次数正規化は既存の考え方であり、**具体的な式と単一置換の新規性は未確認**。革新的と呼ぶ根拠にはまだしない。

採用条件は変えない。単独診断で5/5になっても、同条件・同数の複数反復、初回/履歴あり・題材1/2/3、総入力＋出力token、品質、期限の比較前に本体・READMEの実績・リリースへ採用しない。

## 追加点検で見つかった欠陥：実装へ進めない

同じ相談の中で、recordの粒度を既存traceと生成コードに照合した。unit 3385には共有frame 731とrow atoms 740〜749の10行があり、3431には740〜748の9行がある。未払い費用はそれぞれ542文字と536文字。3617は3385と同じ物理集合で、これらはいずれも未選択である。

`CanonicalSourceRecords.Records.prepare`は空行で区切った段落を作り、その後に字下げによる短いrecordも作る。元native出力の128〜137行の描画費用列`79,46,58,73,66,74,50,80,10,6`がatoms 740〜749と一致し、3385が段落全体、3431が最後の閉じ括弧を欠く段落に対応すると考えられる。ただしtraceにはatom IDからsource keyへの直接対応がなく、これは生成コード・原文・連続費用列による照合である。新たな復元や直接serializedされた座標の検証を行ったとはしない。

最後の行は単独の`}`であり、前の行にも同じ記号がある。したがって重複除去済み字句集合では全体と部分が同じになり得る。その場合、提案した`B(r)`は同点、`B(r)/費用`は短い3431を優先する。**全体候補が存在することだけでは、この式が必要原文の全体を配送できる設計にならない。**
