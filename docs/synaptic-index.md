# シナプス関係のDB所有索引

`Eggshell/SynapseIndex.lean`は推薦関係の保存層である。既存のPageMapのB木を使い、
窓や辺ごとのファイルを作らず、事実・逆引き・入力出版の印を一つの索引出版にまとめる。
認定のMatchやUnionを生成する型・関数ではない。

## 保存と読出し

- DB由来の推薦関係は`derived/<DB identity>/synapses/recommendations/`に置く。
  読み取り専用プロファイルやファイルシステムでは、既存Sidecar規則の私有`read-cache/<DB identity>/`を使う。
- 質問の利用記録は私有の`read-cache/<DB identity>/synapses/usage/`だけに置く。
  質問はダイジェストで識別する。共有DBの推薦関係のレーンは利用記録を拒否する。
- パス・記録指紋・バイト長・行範囲の同一性と、元所有者・元座標への束縛はそのまま保存する。
- `owner / answer / claim / consumer / group / quoted / source / file / query / usage`の逆引きから必要なpostingだけを読む。
  件数・期限の上限に達したらB木の走査を止め、`complete=false`を返す。全件と偽らない。
- 読出しはディレクトリやキャッシュを作らない。初回構築・更新・修復はwarm/背景側の責任である。

各postingは完全なキーと事実の内容アドレスに結び付く。読出し時にキー・内容・範囲・DB・保存レーンを再検査する。
ハッシュだけでは同一視せず、同じアドレスに異なる有効な内容が来たら拒否する。
返す各事実は`CheckedFact key`を持ち、`Lookup.returned_bound`は、返した事実が有効で、
実際に要求キーの逆引き関係に属することを証明する。これは作業の認定や現在のソースの鮮度の証明ではない。

## 原子性と更新

`publishDelta`は事実の追加・削除、全逆引き、件数、入力出版を一度に公開する。
失敗した途中の更新は現在の索引headにならない。古い背景更新が新しい入力出版を上書きすることも拒否する。
同じ内容の再実行は何も追記しない。

利用eventには独立した不変の対応表を置く。同じeventを再送しても増えず、同じeventを違うラベル・範囲・質問に変更できない。
事実の取り下げ後もこの小さな対応表は残すため、削除と追加や全置換でラベル変更を通すことはできない。
DB所有のキャッシュが廃棄されると一緒に消える。

保存した入力headと現在のheadは完全な親headの鎖で照合する。
既存の変更ジャーナルで派生メモだけの更新と確認できた場合だけ、推薦関係を再利用する。
通常の読出しで調べるジャーナルは最大16件で、それを超えたら未知のまま再利用しない。
グラフが変われば推薦関係は古いものとして扱う。一方、私有の利用履歴はDBが成長しても保持する。
その重みから現在のファイルの一致や認定を作ることはない。

索引の実装印はLeanソースの実バイトから導く。手動の版番号やチャットIDは使わない。

## 検証範囲

`tests/SynapseIndexTests.lean`は、実際のネイティブ保存と再読で以下を確認する。

- 再出版の冪等性、増分追加・削除、外部DBの混入と古い更新の拒否、失敗時の非公開。
- グラフ変更による失効と、派生メモだけの更新をまたいだ再利用。
- 件数・期限の途中停止、1000範囲の共引用、eventの再ラベル拒否。
- 私有レーン、別readerからの再利用、実際に書き込み権限を外したDBでの私有索引への退避。

`tools/SynapseIndexProbe.lean`は研究用の接続確認である。
実DBに対応して凍結済みのLean抽出結果を私有索引へ保存し、再出版・別reader・逆引きを確認する。
DBからの自動抽出、索引チケット、`egg warm`、本番フックが接続済みだという意味ではない。
元DBのheadとページファイルのSHAを前後で比較する。

ページ数の値はposting走査だけの値であり、事実の取得やhead検査を含む総I/Oではない。
元DBの実配送やトークン数の改善も、この試験からは主張しない。

2026-10-23のネイティブ試験では、1000範囲中7件のposting走査が3ページ、全件走査が91ページだった。
実DBの凍結済み608関係・47利用記録を私有索引へ保存した後、独立プロセスで抽出ファイルを一切読まず、
索引書込み0で引用支持34件（読者作成込み33ms）・利用記録47件（同12ms）を取得した。
この値はプロセスの`main`内の計測であり、起動前の初期化・モデル・本番フック全体の遅延を含まない。
元DB2個のhead・ページファイルは保存/検索の前後でSHA一致だった。
入力/実行体/ソースのSHAと資源記録は`candidates/synaptic-index-review.json`を参照する。

## 残る接続

DBの出版に応じたLean抽出・増分更新と、隔離したwarm/背景workerへの接続は`SynapseBuild.lean`に実装・検証した。
最新の範囲と記録は`synaptic-build.md`を参照する。
実Pre/Post・私有保存先と受領記録からの継続生成は、隔離候補でネイティブ検証した（`synaptic-journal.md`）。
既存の推薦・配送候補への接続は残っている。
フックで全履歴や全窓の具体化を再開しない。
新しいチャットでの実配送、全6段階の監査、同条件のモデル試験はまだ完了していない。
