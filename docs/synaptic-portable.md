# DBだけで復元できるLeanの導出来歴

`SynapseProvenance.lean`が、実フックで観測したツールの開始・終了を元のネイティブ観測へ結び付けて保存する。
抽出・辺生成・保存・復元はLeanで行う。質問や私有の利用ラベルはこの保存領域へ移さない。

## 保存と復元

元DBの既存の非認定メタデータ領域`memo:synaptic-origin:`に、元所有者のID、完全なsession/turn/tool-use ID、
時計の領域、実際の開始・終了時刻を保存する。本文・入力・出典は元のOutcomeと証明書から取り出す。
`memo:synaptic-state`に件数とハッシュ鎖の終端を原子的に保存する。
順序番号は欠損検査だけに使い、実行時系列には使わない。

同じ観測の再送ではheadを進めず、時刻や元所有者を変えた再送は拒否する。
保存・復元の両方で、固定出版に属する実際のネイティブ観測と照合する。撤回された元観測を起点にしない。
壊れた鎖、欠けた記録、所属が曖昧な観測から関係を作らない。
同じ時計・session・turnの中だけを実時刻で再生し、出力完了と入力開始が同時刻なら消費と扱わない。
来歴の挿入順は関係を変えない。索引を来歴の終端にも結び付け、追加前の索引を準備済みと誤認しない。

headとページファイルだけで、derivedと私有イベントログのない環境へ同じ消費辺を運べる。
ネイティブDBの移送についての性質であり、グラフ値だけのJSON exportについての主張ではない。
読み取り専用のDBでは元DBへ保存せず、既存の私有read-cacheへ索引を構築する。

## 証明と検証

- `Checked.time_order`: 検査済み来歴の開始が終了より厳密に前である。
- `metadata_preserves_authority`: 出版に使うメタデータ行の構成子が、非メタデータのキーを保存する。
  出版ジャーナルは既存の検査済みwriterが別に管理する。
- 原文行への射影、消費の時間順序、逆引きへの所属、私有利用の共有索引への混入拒否の証明も維持する。
  時計・ファイルシステム・フック入力の真実性まで証明するものではない。

ネイティブ試験で、再送・競合・不正時刻・撤回・記録欠損・時計分離・挿入順・非認定行の不変を検査した。
実Pre → 実シェル呼び出し → 実Postを2回行い、背景workerだけで4イベントと2来歴を保存した。
head/ページだけをコピーして書き込み不可にし、別の私有data rootを使う独立プロセスでwarmしたところ、
原文11行目に結び付く消費辺を含む全関係が一致した。元DBへの書き込みもなかった。
読み取り専用共有DBと別の私有作業DBを使う従来の実Pre/Post/Stop試験も通過した。

既存seed37文書の144関係は、以前のLean抽出結果と原文座標まで完全一致し、元DBのhead/ページもSHA-256一致。
初回259ms、再実行2ms・本文の再読0件だった。当該fixtureの測定であり、大規模遅延やトークン削減の保証ではない。
ソース・実行体・失敗を含むguard・証明の依存・実プロトコル記録は`candidates/synaptic-portable-review.json`へ固定する。

## 残件

実フック接続は既存の`candidates/synaptic-ingress.patch`による隔離候補で、本体runtime/installedには未適用。
ビルドは凍結LOCの既存オブジェクトを再利用し、そのPluginModel/保存FFIとの対応も記録する。
現行worktree全体の通常ビルドとは区別する。
推薦・原文配送への統合、全6段階の監査、同条件の総トークン比較、最終採用は未完了。回答モデル・seed追加は0。
導出・共引用・利用からMatch、Union、completedを生成しない。
背景での来歴再生は現状では元記録を再生するため、大規模化の費用も統合時の計測対象に残す。
