# 実フックから更新するLeanの推薦関係

`SynapseJournal.lean`が私有のイベント保存・背景再生、`SynapseLive.lean`が実フックの入口を担当する。
実装にPython、LLM、数値プロバイダは使わない。MiniLMのモデル・数値処理・配送プロンプトは変更しない。
既存のDB直読による引用支持・共引用に、実Pre/Post由来の消費と利用を追加する候補である。

## 観測と受領

- Preではsession/turn/tool-use ID、実入力、質問のSHA-256、対象出版、準備済み索引のhead、受領済みの原文区間キーを保存する。
  現在のPreToolUse自身による配送より先に知識を固定する。再送で最初の知識・時刻を更新しない。
- Postでは同じ実IDと入力・出力、実観測を出版する保存先を記録する。背景側で完全なネイティブOutcomeと照合する。
  未出版なら待ち、保存先がない/確認不能な観測から保存済みという事実を作らない。
- Stopはフックが提供した最終本文と受領済み区間を使う。フック由来のIDを明示し、存在しないagentMessage IDとは扱わない。
- 未受領・期限切れ・取り落としたofferがあれば、受領できていないこと自体も確定しない。
  不明の印をコンテキスト破棄まで保持し、その場合は未配送ラベルを作らない。
  受領済みの位置案内や制御キーを、本文の配送として扱わない。

時刻はフック入口で観測したmonotonic nanosを使う。イベントファイルの列挙順や書込順は実行順に使わない。
daemonごとに更新される秘密値のハッシュと、既存のコンテキストepochで時計の領域を分ける。秘密値自体は保存しない。
異なる領域の出力や、同時刻・順序不明のイベントから消費を推定しない。
文字列一致による消費の推定は推薦用のヒューリスティックである。

## 背景更新と私有境界

イベントは`read-cache/<DB identity>/synapses/events/`の一つのPageMapへ、4 KiBのチャンクとturnの逆引きで原子的に保存する。
イベント名は種類と完全な実IDで決まり、同じ観測の再送は増えない。内容を変えた再送は拒否する。
本文は1イベント8 MiBまでとし、途中を切って完全な観測と偽らない。

数値設定を持たない専用のDB所有targetを登録する。既存のindex workerとdrainの排他を共有し、
`semantic_matcher`がなくても背景更新される。空のプロバイダコマンドや外部の抽出プロセスは作らない。
現在のチャットの読み取り専用設定は、以前のwriter登録より優先する。

背景側は最大8 turnと期限で区切る。未出版のPostと残りturnは回収対象に残す。
入力が派生メモだけの変更なら、元本文を再生しない。
進捗はDBの完全なhead・入力件数・保存レーン・索引のincarnation・Leanの実バイトに結び付ける。
キャッシュを捨てて作り直した場合も、イベントから消費辺を再構築する。
過去のPreが参照した索引を失っていたら、その利用ラベルは不明にし、既存の不変の利用記録を再ラベルしない。

読み取り専用の共有DBを読み、実行結果を私有の作業DBへ出版した場合も、保存先の実Outcomeと照合して利用を記録する。
以前に私有DBから観測した範囲も受領済みとして数え、同じ範囲を繰り返し未配送と呼ばない。
私有の呼び出しを、共有DBの消費辺へ流さない。共有の消費は両端が対象の固定出版に存在する場合だけにする。
DB identityが等しくても、後から進んだheadや別のコピーの観測を、その出版の所属と取り違えない。

`file`逆引きでPreの保存済み読み取り範囲を調べる。フックの中で全文書や全ベクトルを走査しない。
JSONオブジェクトの一意な`output`/`aggregatedOutput`/`stdout`も、元のJSON内のUnicode座標へ戻して扱う。
複数の対応がある出力は不明のままにする。

## 証明と検証

実際の保持・判定関数について、再送が最初の観測を保つこと、完全な知識が不確かな配送を含まないこと、
対象出版に属さない出力が公開側のTraceを変えないこと、時計の領域化が観測時刻を変えないことをLeanで証明する。
既存の範囲内支持、実時間順、要求キーへの所属、証拠joinの性質も維持する。
I/Oの時計やネイティブフックが真実を返すことまでをLeanの定理としない。
推薦の保存・重みからMatch・Union・completedの認定は生成しない。

ネイティブ試験で、未配送1区間・部分配送の欠落2区間、原文行へ射影された消費10証拠、再送の冪等性、
並行呼び出し・異なる時計・キャッシュ再構築・派生メモ・共有DBと私有保存先の分離を検査する。
同じDB identityの後続出版を、固定した古い出版の所属にしない検査も含む。

隔離実行体を使った試験では、実Pre → シェルでの実読み取り → 実Post → save worker → Stopを実行した。
共有DBを読み取り専用で使い、実行結果は別の私有DBへ保存した。
試験側から再生関数を呼ばず、背景workerだけで未配送後再読と最終回答の引用が記録されることを確認する。
共有DBのhead/ページは不変、回答モデル呼出し0である。
実行体・ソース・失敗したビルド・成功した試験・資源記録は`candidates/synaptic-journal-review.json`に固定する。

## 適用範囲と残件

実フックへの接続は`candidates/synaptic-ingress.patch`で隔離している。このパッチは前段のwarm接続も含む。
本体のruntimeファイルやインストール済み実行体には未適用である。
検証実行体は凍結LOCの既存オブジェクトを再利用する。残したPluginModelには`searchStarted`診断フィールドがあり、
保存FFIにはLOCの既存ディレクトリ読出し拡張もある。現行worktreeの全ソースを通常ビルドした証拠とは区別する。
依存ソース/オブジェクトも実記録へ含める。

続く候補では、書き込み可能な元DBへ質問を含まない導出来歴を保存し、DB単体からの復元も検証した。
詳細と独立プロセスの証拠は`synaptic-portable.md`を参照する。私有の利用ラベルを共有DBへ移すものではない。
推薦・原文配送への接続、全6段階の監査、モデル比較、最終採用は残っている。
この試験のフックはモデルを呼ばず、検索配送も無効にしている。30秒以内の一般的な実配送やトークン改善の実証には使わない。
